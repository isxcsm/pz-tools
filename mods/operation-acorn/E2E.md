# OA 통합 게임 테스트 (E2E) 계획

임무, 연출, 수치형 적응을 실제 게임에서 끝까지 돌려 본다. 각 항목은 "의도대로 도는가"와 "유저 눈에 어색하지 않은가"를 함께 본다.
어색한 것은 보이는 즉시 고치고, 아래 [발견 기록](#9-발견-기록)에 남긴다. 미루지 않는다.

> **2회차 완료 (2026-10-16).** 두 차례 다 돌렸고, 다시 확인한 점검은 모두 통과했다. 1~7장의 체크박스는 항목별로 채우지 않았다:
> 빈 칸이 남은 일을 뜻하지 않는다. 남은 일은 8장 보류 항목의 빈 칸뿐이다.

## 0. 진행 방식

- **세이브**: 버리는 세이브를 쓴다 (`OperationAcornDev` 켬, `-debug`). 기능별로 깨끗한 세이브가 필요하면 새로 만든다.
- **도구**: `../tools/pzdev.py`(run, file, check, shot, reload, continue, resume), 디버그 패널(F8), `tests/ingame/p*_*.lua`.
- **순서**: 묶음별로 정적 점검(단위 테스트, 번역 검사)을 먼저 돌리고, 게임 확인은 묶음마다 한 번에 몰아서 한다.
  1. 수치형 적응 (2장): 값이 정해져 있어 바닐라와 비교하기 쉽다.
  2. 연출 (3장): 타이틀, 교신, 창, 월드 표시.
  3. 임무 (4장): 시간이 가장 오래 걸린다. 디버그로 단계, 신뢰도, 시간을 당긴다.
  4. 공통 예외 (5장), 언어와 화면 조건 (6장).
- **기록**: 체크박스는 확인한 것만 채운다. 실패하거나 어색하면 발견 기록에 한 줄 남기고, 고친 커밋을 적는다.
- **판정**: 숫자는 바닐라 기준값과 나란히 잰다 (같은 캐릭터, 같은 장소, 노드만 바꿈). 연출은 스크린샷을 남긴다.
- **밤 시야 측정**은 새벽 2시에 한다 (메모리 규칙).
- **원칙**:
  - 고친 뒤에는 해당 영역 테스트만 돌린다. 전체 테스트는 묶음이 끝날 때 돌린다.
  - 확장 API를 바꾸면 빌드, `pzext-install`, 게임 재시작까지 해야 반영된다.
  - 텍스처를 바꾸면 게임을 재시작한다. Lua와 번역은 `pzdev reload`로 충분하다.

### 2.4 연장 투여 (2번째 판)

나눔(divide), 더함(add), 다가감(approach) 세 공식이 기본 노드와 어떻게 겹치는지 본다. 단계가 많을 때(20, 50) 값이 상한을 넘지 않는지도 본다.

- [ ] 하중 줄: 자재·가구 경량화, 장비·보급품·잡동사니 경량화(범주 묶음), 장비 적응, 장비 속도 적응, 과적 숙련, 손놀림, 운반 한도, 수납 공간
- [ ] 생존 줄: 상처 감염 내성, 질병 내성, 물림 회복, 근육통 내성, 지구력, 졸음 내성, 장비 보존, 낙하 충격 완화, 질주 지구력, 이동 속도(상한 0.40)
- [ ] 정찰 줄: 전리품(상한 1.00, 미개봉만), 선별 시료(+30%p 상한), 시료 묶음(+0.02씩)
- [x] 단계 비용 ceil(k/5)이 적용 계획 막대와 실제 차감에서 같은지

스타일 (dust, discovery, unveil, notice, stamp, bleed, sink, type, pulse) 별로, 그리고 실제 발생 지점별로 본다.
디버그 '연출' 페이지 버튼 15개와 실제 게임 이벤트를 모두 거친다.

- [ ] 최종 적응 (dust, 금색, 이름 / 최종 적응), 연장 투여 개시 (dust)
- [ ] 적응 완료 (금색), 계열 초기화 (호박색), 감염 진행 멈춤, 지연제 효과 상실 (sink, 붉음)
- [ ] 감염 양성 (bleed), 음성 (pulse), 감염 완치 (pulse, 초록), 물림 감염 차단, 물림 내성 회복
- [ ] 수색 완료와 보너스, 다 뒤진 건물, 처치 수, 시료 대장 종류·범주
- [ ] 새 요청, 요청 완료, 요청 지역, 요청 물품 소실(찾기·흙·바꿔치기·표적), 기한 경과
- [ ] 신뢰도 단계 카드(이름 있는 1~5단계는 단말 열 때, 오를 때는 "단말에서 확인" 타이틀), 6단계 이후 타이틀, 담당 부서 변경, 정식 단말 개통

### 10.1 P 성능 (전후 비교)

- **기준:**
  - 전(c0)은 성능 병합 직전 dev 커밋, 후(c1)는 이번 dev다. 같은 세이브, 같은 장소, 같은 동작으로 잰다.
  - 도구는 `pzdev profile`(JFR: 뜨거운 메서드와 GC 멈춤, 프레임 시간은 아니다)과 `tests/ingame/perf_r3.lua`(Lua 타이밍 래퍼와 프레임 기록: p50·p95·p99, 50ms 넘는 프레임 수)다. 경로 이름의 c0/c1 짝과 재는 방법은 `perf_r3.lua` 머리말에 있다.
  - 첫 좀비 2.6초 멈춤은 우리 것이 아니다. 세션마다 첫 좀비를 먼저 지나 보내고 잰다.
  - 기계 10대, BU 제어반 3개와 접속함·스프링클러 선, 집·차 경보 6개씩과 경보 읽기 노드는 하네스가 직접 놓고 끝에 거둔다. 세이브에 미리 없어도 된다. 무대와 운석 터는 월드에 지어지니 끝나고 세이브를 되돌린다.
  - 전후는 이 순서로 바꾼다. c0 작업본은 `C:\git\pz-workspace\wt-c0`(a4692230, API 빌드해 둠), c1은 본 체크아웃(dev)이다. `perf_r3.lua`는 dev에 들어가 있어야 한다(`Zomboid\Lua\oa` 정션이 본 체크아웃을 가리킨다).
    1. 게임을 닫고(`pzdev quit`) 세이브를 보관한다: `python mods/tools/pzdev.py snapshot r3-perf --save BU_Spawn_E2E`. 되돌릴 때는 `restore r3-perf` (이미 있는 `clean`은 건드리지 않는다).

### 10.4 U 연출과 UI/UX

- [x] **지도 (세계 지도, 상태를 만들어 찍음; 미니맵은 안 봄):** 미션 원, 측량 원(호박), 마굴 원(키트 색, 뒤에 한 색으로: 116)이 함께 있어도 구분된다. 흐린 원이 길 안내와 섞이지 않는다. 겹치는 마굴 원은 하나로 합쳤다 (9장 102).
- [x] **상점:** 재고와 재입고 시각 표시가 카드 안에 들어가고, 품절 카드가 흐려지는 정도가 알맞다. 품절 카드의 값은 재입고 때 값으로 (9장 103).
- [x] **겹침:** 같은 순간 타이틀 여럿이 줄을 선다. 정산 타이틀, 이스터에그 타이틀, 등급 스탬프가 한꺼번에 와도 순서가 자연스럽다.
- [ ] **흐름 미리 걷기 (메모리 규칙):** (코드로 추론만 했다, 10.6에서 플레이로) 측량은 노티스 → 교신 → 호박 원 → 낙하 지점 타이틀 → 납품 → 최종 적응 타이틀로 끝 신호가 있고, 그만두면 원이 레코드에 남는다. 마굴은 원 가운데까지 가야 판정이 돌았다: 합친 큰 곳은 가운데가 빈 길일 수 있어 원 안이면 돌게 고쳤다 (9장 106).
  - 캡스톤 → 노티스 → 단말 → 교신 → 지도 → 현장 → 납품 → 캡스톤 열림
  - 마굴 원 → 현장 → 소탕 → 상점
  - 각 단계 사이가 갑자기 끊기지 않는지, 끝 신호가 있는지, 중간에 그만둔 경로가 있는지 본다.
