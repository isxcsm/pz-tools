# OA 플레이 흐름 점검

플레이어 입장에서 흐름을 단위별로 점검한다. 지금 동작을 적는 문서가 아니다. 플레이어가 이상하거나 허전하게 느낄 곳을 찾고, 그런 곳이 있으면 구조를 고친다.

방법:
1. 단위마다 아래 점검 축을 모두 판정한다. 빈칸을 남기지 않는다. 해당 없는 축은 "해당 없음"이라고 쓴다.
2. 판정은 **통과**, **문제**, **게임**(코드로는 판단할 수 없어 게임에서 볼 것) 중 하나다. 근거는 코드나 문서로 확인한 사실을 쓴다.
3. 문제는 [고칠 목록](#고칠-목록)으로 모아 한 번에 고친다. 게임 판정은 [게임 확인 목록](#게임-확인-목록)으로 모아 고친 뒤 한 번에 본다.
4. 기능을 새로 만들거나 손볼 때는 그 단위를 다시 판정한다.

## 점검 축

| 축 | 묻는 것 |
| --- | --- |
| 행동 반응 | 플레이어가 한 일마다 바로 반응이 있는가 (집기, 넣기, 밀봉, 호출, 착수) |
| 다음 할 일 | 지금 무엇을 해야 하는지 화면이 알려 주는가 |
| 결과 확인 | 끝났을 때 얻고 잃은 것이 그 자리에서 보이는가 |
| 자리 비움 | 단말이나 아지트를 떠나 있을 때, 알아야 할 일은 알고 몰라도 될 일로 시달리지는 않는가 |
| 되돌아오기 | 끊기거나 건너뛰거나 나갔다 와도 이어 갈 수 있는가 |
| 반복 피로 | 열 번째에도 거슬리지 않는가 (확인창, 연출 길이, 알림 빈도) |
| 몰림 | 여러 일이 한꺼번에 올 때 순서와 양이 괜찮은가 |
| 공통 규칙 | 아래 규칙을 지키는가 |

점검할 때 다른 게임은 같은 순간을 어떻게 처리하는지도 떠올린다 (예: 무전은 호출음이나 잡음으로 시작한다).

## 공통 규칙

- **바닐라 일시정지를 가리지 않는다.** 모드가 스스로 게임을 멈추지 않고, 일시정지 표시 위에 아무것도 그리지 않는다. 플레이어가 기대하는 기본 동작이다.
- **일시정지면 연출도 멈춘다.** 저절로 흘러가는 장면은 장면 시계(`UI.sceneNow`)로 돈다: 교신, 타이틀(API), 연구 배너, 감각 표시, 헬기 소리, 현장 교신. 다시 흐르면 그 자리부터 이어 간다.
- **조작하는 UI는 멈추지 않는다.** 창이 열리고 닫히는 페이드, 클릭 반짝임, 단말 부팅 화면, 문서가 펼쳐지는 모습, 지도 표시는 일시정지 중에도 바닐라 창처럼 움직인다. 멈춰 있을 때 단말과 지도를 쓰는 것도 기본 동작이다.
- **이름과 문장.** 이름표 자리(아이템, 카드 제목)는 명사형, 문장 자리는 사람 말. 같은 물건은 어디서나 같은 이름.

## 단위별 판정

### 1. 단말 열기와 부팅

흐름: 단말 우클릭 → 쓰는 동작 → 부팅 콘솔 → 탭 페이드 (교신이 기다리면 교신 탭, 아니면 상태 탭) → 닫기.

| 축 | 판정 | 근거 |
| --- | --- | --- |
| 행동 반응 | 통과 | 동작이 끝나면 바로 창과 부팅 화면. 전기가 없으면 "단말에 전기가 들어오지 않습니다" |
| 다음 할 일 | 통과 | 기다리는 교신이 있으면 교신 탭으로 연다 (Terminal.opening) |
| 결과 확인 | 해당 없음 | |
| 자리 비움 | 해당 없음 | |
| 되돌아오기 | 통과 | 재생 중에 닫으면 건너뛴 것으로, 호출 중이면 취소 (단위 3) |
| 반복 피로 | 통과 (결정) | 조립 단말 부팅은 약 15초지만 클릭으로 넘긴다. 줄이지 않기로 함 (2026-10-18) |
| 몰림 | 통과 | 오래 비운 뒤 열면 단계 카드 → 밀린 교신 → 새 임무 순으로 하나씩 (G1) |
| 공통 규칙 | 통과 | 부팅은 조작 UI라 일시정지 중에도 돈다 |

### 2. 교신이 오는 것을 알기

흐름: 교신이 대기열에 든다 → 아지트 단말 외곽선 깜빡임, 게임 10분마다 잡음 (전기가 있을 때만) → 단말을 연다.

| 축 | 판정 | 근거 |
| --- | --- | --- |
| 행동 반응 | 해당 없음 | |
| 다음 할 일 | 통과 | 외곽선과 잡음이 단말로 부른다 |
| 결과 확인 | 해당 없음 | |
| 자리 비움 | 통과 | 아지트 밖에서는 모른다. 교신은 단말에서만 한다는 설계 (CANON S11a). 놓쳐서 손해 보는 일은 없다 |
| 되돌아오기 | 통과 | 교신은 들을 때까지 기다린다 |
| 반복 피로 | **문제** | 잡음이 게임 10분(기본 속도 약 25초)마다 계속 난다. 아지트에서 다른 일을 하는 내내 울린다 → P5 고침 |
| 몰림 | 해당 없음 | |
| 공통 규칙 | 통과 | 게임 10분 이벤트라 일시정지 중엔 울리지 않는다 |

### 3. 교신 재생 (임무 착수 브리핑 포함)

흐름: (착수 확인 →) 교신 탭 → 호출 연출 (잡음, "참나무 호출 중 · · ·", "회선 연결") → 대사 → 끝 → 기록에 접힘.

| 축 | 판정 | 근거 |
| --- | --- | --- |
| 행동 반응 | 통과 | 착수하면 교신 탭으로 넘어가 호출 연출. 호출 중 위 표시는 "연결 중" (고침 2026-10-18) |
| 다음 할 일 | 통과 | 브리핑이 끝나면 "임무 착수" 타이틀 (고침 2026-10-18) |
| 결과 확인 | 통과 | 기록에 남고 다시 재생할 수 있다 |
| 자리 비움 | 해당 없음 | |
| 되돌아오기 | 통과 | 호출 중 나가면 취소되고 카드에 "교신 보기". 대사가 나온 뒤 나가면 건너뛴 것으로 (고침 2026-10-18) |
| 반복 피로 | 통과 | 건너뛰기는 호출 연출만 넘기고 첫 줄부터 |
| 몰림 | 통과 | 밀린 교신은 1.5초 간격으로 연달아. 앞의 것은 첫마디와 다시 재생 버튼으로 접힌다. 브리핑 뒤에는 탭을 떠날 때까지 미룸 (G2) |
| 공통 규칙 | 통과 | 교신 중에도 게임이 흐르고, 일시정지면 타이핑과 잡음이 멈춘다 (게임 확인 2026-10-18) |

### 4. 납품 상자: 놓기, 담기, 밀봉

흐름: 상자 놓기 → 담기 (예상 정산 패널, 툴팁 정산가) → 우클릭 밀봉 → 확인창 → "상자 밀봉 / N점" 도장.

| 축 | 판정 | 근거 |
| --- | --- | --- |
| 행동 반응 | 통과 | 담으면 패널 값이 바뀌고, 밀봉하면 도장 타이틀 |
| 다음 할 일 | 통과 | 상태 탭에 "밀봉한 납품 상자 N개"와 헬기 호출 버튼. 단말은 보통 상자 곁에 있다 |
| 결과 확인 | 통과 | 예상 정산이 패널과 상태 탭에 |
| 자리 비움 | 해당 없음 | |
| 되돌아오기 | 통과 | 밀봉 전에는 언제든 넣고 뺀다 |
| 반복 피로 | 통과 | 밀봉 동작이 약 5초라 붙은 상자 둘을 연달아 봉해도 도장 타이틀이 겹치지 않고 하나씩 나온다. 크기는 작게 (G3) |
| 몰림 | 해당 없음 | |
| 공통 규칙 | 통과 | |

### 5. 헬기 호출부터 투하와 정산까지

흐름: 헬기 호출 → 확인창 (상자 수, 예상 정산, 주문, 잔액) → 도착 막대 → 헬기 소리 → 상자 걸어 올림, 보급 상자 투하 → "투하 완료 / 지도에 표시됨" → 정산.

| 축 | 판정 | 근거 |
| --- | --- | --- |
| 행동 반응 | 통과 | 확인창, 도착 막대, 카드 "호출했습니다." |
| 다음 할 일 | 통과 | 투하 완료와 지도 표시가 상자로 부른다 |
| 결과 확인 | **문제** | 일반 납품은 얼마 받았는지 화면에 안 나온다. "투하 완료" 밑줄은 "지도에 표시됨"뿐이고, 크레딧과 신뢰도는 단말을 열어야 보인다 (임무 정산만 "요청 완료 · N 크레딧") → P2 고침 |
| 자리 비움 | 통과 | 투하 완료 타이틀은 어디서든 뜬다 |
| 되돌아오기 | 통과 | 창을 닫아도 헬기는 온다 |
| 반복 피로 | 통과 | 확인창에 숫자가 있어 볼 만하다 |
| 몰림 | 통과 | 단계 → 새 요청 → 투하 완료(정산액) 순으로 줄 선다. 하나하나 읽을 수 있다 (G4) |
| 공통 규칙 | 통과 | 헬기 소리는 장면 시계 (고침 2026-10-18) |

### 6. 주문

흐름: 주문 탭 → 장바구니 → 헬기 호출 때 실림 → 도착 때 결제 → 보급 상자.

| 축 | 판정 | 근거 |
| --- | --- | --- |
| 행동 반응 | 통과 | 담으면 장바구니와 합계가 바뀐다 |
| 다음 할 일 | 통과 | "결제는 헬기가 도착할 때 합니다", 모자라면 이번 편 정산분까지 더해 결제한다고 알린다 |
| 결과 확인 | 통과 | 보급 상자와 명세서 |
| 자리 비움 | 해당 없음 | |
| 되돌아오기 | 통과 | 장바구니는 남는다 |
| 반복 피로 | 통과 | 빈 장바구니의 버튼이 "지난 주문 다시 담기"가 된다. 지금 살 수 있는 것만, 주간 한도 안에서 담는다 (G5) |
| 몰림 | 해당 없음 | |
| 공통 규칙 | 통과 | |

### 7. 보급 상자 열기

흐름: 상자 열기 → 꺼내기 → 비면 부서져 나무와 못이 떨어진다 → 명세서 비고.

| 축 | 판정 | 근거 |
| --- | --- | --- |
| 행동 반응 | 통과 | 비면 부서진다 |
| 다음 할 일 | 통과 | 명세서 비고가 덤을 알려 준다 |
| 결과 확인 | 통과 | 루팅 창에 다 보인다 |
| 자리 비움 | 통과 | 상자는 남는다. 상태 탭에 "주변에 남은 보급 상자" |
| 되돌아오기 | 통과 | 일부만 꺼내도 상자는 남는다 |
| 반복 피로 | 통과 | |
| 몰림 | 해당 없음 | |
| 공통 규칙 | 통과 | |

### 8. 신뢰도 단계 오름

흐름: 정산으로 신뢰도가 오른다 → 이름 있는 1~5단계는 다음에 단말을 열 때 단계 카드, 6단계부터는 그 자리에서 타이틀 → 단계 교신 → 새 품목.

| 축 | 판정 | 근거 |
| --- | --- | --- |
| 행동 반응 | 해당 없음 | |
| 다음 할 일 | 통과 | 카드 밑줄 "목록에 새 품목 추가" |
| 결과 확인 | **문제** | 1~5단계는 오르는 순간 아무것도 안 뜬다 (Story.stageTitle이 nil). 큰 진전인데 단말을 열 때까지 모른다 → P3 고침 |
| 자리 비움 | **문제** | 위와 같은 이유로, 정산 때 밖에 있으면 단계가 오른 줄 모른다 → P3 고침 |
| 되돌아오기 | 통과 | 카드는 단말을 열 때까지 기다린다 |
| 반복 피로 | 통과 | 단계는 드물다 |
| 몰림 | 통과 | G1, G4 |
| 공통 규칙 | 통과 | |

### 9. 임무 대기와 착수

흐름: "새 요청 / 단말 임무 탭 확인" → 대기 카드 ("착수 후 N일") → 착수 → 확인창 → (이야기 임무는 단위 3) → "임무 착수".

| 축 | 판정 | 근거 |
| --- | --- | --- |
| 행동 반응 | 통과 | 확인창, 탭 전환 또는 타이틀 |
| 다음 할 일 | 통과 | 카드에 남은 날과 "지도에서 보기" |
| 결과 확인 | 통과 | |
| 자리 비움 | 통과 | 새 요청 타이틀은 어디서든 뜨고, 대기 중엔 기한이 흐르지 않는다 |
| 되돌아오기 | 통과 | 대기 카드는 그대로 기다린다. 다시 받기 가능 |
| 반복 피로 | 통과 | 착수 확인은 기한이 걸린 약속이라 매번 묻는다 |
| 몰림 | 통과 | 새 이야기 임무는 대기 중인 일반 임무 자리를 대신한다 |
| 공통 규칙 | 통과 | |

### 10. 임무 수행 공통: 현장, 확보, 납품, 결과

흐름: 지도 → 현장 ("요청 지역" 타이틀) → 물건 외곽선 → 집기 → 아지트로 → 납품 상자에 넣고 밀봉 → 헬기 → "요청 완료 · N 크레딧".

| 축 | 판정 | 근거 |
| --- | --- | --- |
| 행동 반응 | **문제** | 임무 물건을 집어도 일반·계약 임무는 아무 반응이 없다. 이야기 임무만 혼잣말 (Missions.found) → P1 고침 |
| 다음 할 일 | **문제** | 물건을 집은 뒤에도 카드는 집기 전과 같다 (it.found를 카드가 쓰지 않는다). 다음 할 일(넣고 밀봉, 헬기)이 안 보인다. 밀봉 뒤 문구는 고침 (2026-10-18) → P1 고침 |
| 결과 확인 | 통과 | "요청 완료 · 임무 · N 크레딧" |
| 자리 비움 | **문제** | 기한이 다 돼 가도 경고가 없다. "급함" 표시는 카드에만 있고, 밖에서는 "요청 기한 경과"가 처음 받는 신호다 → P4 고침 |

| 반복 피로 | 통과 | |
| 몰림 | 해당 없음 | |

### 11. 이야기 임무의 특수 흐름

| 임무 | 판정 | 근거 |
| --- | --- | --- |

## 결정 기록

- 2026-10-18: 단말 부팅(약 15초)과 다 읽은 문서의 다시 타이핑은 그대로 둔다. 클릭으로 넘길 수 있어 불편하지 않다.
- 2026-10-18: 교신은 게임을 멈추지 않는다. 일시정지면 장면이 멈춘다.
- 2026-10-18: P1~P6 고침. 세부 판단:
  - 확보 타이틀의 밑줄은 물건 이름 대신 임무 제목(일반 임무 제목이 곧 물건 이름). 여럿 모으는 임무는 "제목 · 2/3".
  - 비교 임무는 확보 타이틀도, 카드의 확보 문구도 없다. 둘 중 어느 쪽이 맞는지는 플레이어가 판단할 몫이다.
  - 카드의 "확보했습니다. 납품 상자에 넣고 밀봉하십시오."는 모을 것을 다 모았을 때만. 그 전에는 외곽선 안내 그대로. 좀비 임무에는 외곽선 안내를 띄우지 않는다 (보관함이 아니라 시체에서 얻는다).
  - 투하 정산액은 감염 처리 수수료를 뺀 값. 요청 정산 타이틀과 따로 나온다 (요청 하나 몫과 이번 비행 전체 몫).
  - 첫 접촉으로 열리는 1단계는 단계 타이틀을 띄우지 않는다. 그때는 단말이 열려 있고, 첫 교신 뒤 카드가 나온다.
  - 기한 경고는 처음부터 이틀 미만인 임무에는 없다 (카드가 처음부터 짧다고 말한다). 분실 등으로 기한이 늦춰지면 다시 경고한다.
  - 교신 잡음은 새 교신이 들어오거나, 단말이 범위 밖에 있다가 돌아오면 처음 세 번부터 다시.
- 2026-10-18: 착수 흐름 고침: 호출 중 나가면 취소, 건너뛰기는 호출만, 브리핑 뒤 "임무 착수" 타이틀, 다음 교신 미룸, "연결 중" 표시, 밀봉 카드 "헬기를 부르면 정산됩니다".
- 2026-10-18: 게임 확인 G1~G6 마침. 세부 판단:
  - 타이틀 크기 단계: 큰 장면(도토리 작전, 단계 카드, 인계, 최종)은 크게, 자주 나오는 큰 스타일(밀봉 도장, 확보, 키트)은 작게. 알림 스타일은 이미 작아 줄이지 않는다. 도토리 작전은 도토리색.
  - 임무 탭의 제안 카드와 잠긴 특별 의뢰 칸은 내용 높이에 맞춘다.
  - 찾을 물건은 가져올 물건 기준. 바꿔치기에서 두고 오는 보관 용기가 아니라 기록철.
  - 진행 중 임무 물건의 툴팁은 "정산가 약 0 크레딧" 대신 "임무 보수로 정산".
  - 현장 거래에 머무르기 조건을 새로 만들지 않는다. 호출 뒤에는 물건이 이미 넘어갔고, S5F/S8F에서 2반이 안전 반경 밖으로 나가라고 한다.
