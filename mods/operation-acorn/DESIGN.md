# Operation Acorn (도토리 작전) 설계

Project Zomboid B42용 모드. 이름은 Operation Acorn, 한국어로 도토리 작전이다. 연구팀이 붙인 군 작전명이라 세계관 안에서
자연스럽고, '도토리'가 모아 두는 다람쥐 플레이를 가리킨다.

- 모드 ID `OperationAcorn`. 세이브 키와 전역 modData 키는 `OA_`로 시작한다. 이름을 바꾸면 세이브가 깨지므로 고정한다.
- 워크숍에 같은 이름이 없다 (2026-10-09 검색: "Operation Acorn" 0건, "Acorn" 29건 중 겹치는 이름 없음).

## 1. 목적

후반 플레이의 핵심 재미는 도시의 자원을 다람쥐처럼 아지트로 모으는 것이다. 그런데 필요한 것을 다 갖춘 뒤에는
더 모을 이유가 없다. 이 모드는 **모으는 일 자체에 보상**을 붙여서 후반에도 파밍할 동기를 만든다.

- 파밍한 물건으로 캐릭터를 키운다 (강화 트리).
- 파밍한 물건으로 연구팀과의 관계를 키운다 (평판 상점).
- 둘 다 더 멀리, 더 많이 파밍하게 만든다.

**대상은 고인물 유저다.** 게임에서 할 것이 없어 조금 하다 접는 유저에게 새 재미를 준다. 초보를 돕는 모드가 아니다.
그래서 모든 강화는 '지도와 공략을 다 아는 사람에게도 새로운가'로 고른다.

## 2. 설계 원칙

| 원칙 | 내용 |
| --- | --- |
| 양보다 발견 | 같은 물건을 반복해서 얻는 것보다 처음 찾은 것에 더 크게 보상한다. 넣었다 빼는 식의 꼼수가 통하지 않게 한다. |
| 다람쥐 순환 | 밖에서 모으고 → 아지트로 실어 오고 → 아지트에서 처리하는 흐름이 모든 시스템의 중심이다. |
| 제한은 성장으로 | 벌칙으로 막지 않는다. 처음엔 작게 주고, 성장할수록 늘려 준다 (예: 납품 상자 용량). 불필요한 스트레스는 주지 않는다. |
| 실물 아이템 | 보상은 되도록 손에 쥐는 아이템으로 준다 (교범, 기계 부품, 혈청). 아지트에 쌓아 두는 재미와 이어진다. |
| 원작의 톤 | 사태의 원인은 원작처럼 모호하게 둔다. 떡밥만 주고 답은 확정하지 않는다. |
| 추가하지 고치지 않는다 | 바닐라 아이템과 레시피를 고치지 않고 새로 추가한다. 다른 모드와의 충돌을 줄인다. |
| 다른 특성 모드와 호환 | 다른 특성·직업 모드의 영역을 되도록 침범하지 않고, 같이 켜도 돌아가게 한다. 바닐라 값을 고정값으로 덮어쓰지 않고 배율이나 더하기로 얹는다. |
| 효과는 계산 지점에 얹는다 | 강화 효과는 PZ Extension API가 바닐라의 최종 계산 지점(Java)에서 배율이나 더하기로 얹는다. Lua 함수를 덮어쓰거나 아이템·캐릭터 값을 직접 쓰지 않는다. 그래야 다른 모드의 덮어쓰기가 살아 있고, 로드 순서와 상관없이 같이 돈다. API에는 내용 없이 보정 장치(무게, 행동 시간, 운반 한도 등)만 두어 다른 모드도 쓸 수 있게 한다. Java 지점이 없고 Lua에서만 계산되는 값은 Lua에서 감싸되(덮어쓰지 않음), 기능마다 어느 쪽인지 조사한다. 같은 효과를 주는 다른 모드와의 중첩(밸런스)은 영역을 나누거나 상한을 두어 설계로 푼다. 바닐라에 박힌 상한(용기 용량 100, 줍기 한도 50 등)은 API가 걷어내서 강화가 상한에 막히지 않게 한다. |
| 이벤트 기반 | 칸(square)마다 도는 처리를 만들지 않는다. 필요한 정보는 이벤트로 받는다. |
| PZ Extension API 사용 | Lua 모드지만 PZ Extension API를 전제로 만든다. Lua로 느리거나 불가능한 일(주변 감지, 무게 계산, 게임 공식 보정)은 API로 한다. API 없이 도는 판은 만들지 않고, 나중에 필요해지면 그때 따로 검토한다. API가 없으면 모드는 아무것도 바꾸지 않고 안내만 한다. |

## 3. 세계관

- **설정의 기준은 [세계관 설정집](LORE.md)이다.** 이 장은 요약이다. 연구팀, 단서, 인물, 이야기 막, 결말, 문구는 설정집을 따른다.
- **무전 너머의 연구팀.** 육군 환경시료 분석 파견대 제2반(호출부호 '참나무')이 무전으로 연락해 온다. 구역 밖 어딘가에
  있고 정확한 위치는 끝까지 밝히지 않는다. 생활용품 시료와 재료를 보내 주면 물자와 연구 결과를 보내 준다. 플레이어는
  세이브마다 다른 네 자리 '채집점 번호'로 불린다.
- **첫 보급.** 바닐라 헬기 이벤트가 사실은 연구팀이다. 첫 헬기가 지나갈 때 캐릭터가 있던 집 앞 도로(가까운 빈터)에
  납품 상자 하나를 두고 간다. 상자 안에는 다 조립된 통신 단말, 조립법 책자, 채취용 메스가 들어 있다. 숨은 절차(주파수 찾기) 없이, 누구나
  겪는 바닐라 사건에서 모드가 시작된다. 그 뒤의 거래, 주문, 헬기 호출은 조립한 통신 단말로 한다 (9장).
- **NPC는 두지 않는다.** 무전 교신과 **헬기 투하**가 연구팀을 대신한다. B42에는 인간 NPC가 없고, 만들려면
  모드 전체보다 일이 크다.
- **떡밥.** 원작의 라디오 방송은 사태 직전의 이상한 기상 현상과 공기 중의 이상한 냄새를 언급한다. 연구팀의 무전은
  진행할수록 이쪽으로 흘러간다.
  - 초반: 재료와 시료만 요구한다.
  - 중반: "대조표에 일치하는 항목 없음", "기준일 무렵 관측 기록을 찾아 달라."
  - 후반: 연락이 점점 끊긴다. 외계 기원을 확정하지 않는다.
- **잡템을 가져가는 이유.** 연구팀에게는 두 가지 동기가 있다.
  - **시료:** 기준일 밤 공기 중의 무언가가 생활용품 표면, 옷감, 필터에 남아 있다. 연구팀은 감염이 어디서 어떻게
    퍼졌는지 추적하려고 지역별 시료를 모은다. 의류, 천, 생활용품, 필터류가 여기에 해당한다. 원작의 '이상한 냄새'
    떡밥과 이어진다.
  - **물자:** 봉쇄선 밖에서 부족한 부품과 재료다. 전자제품, 공구, 금속이 여기에 해당한다.
  - 이 설정이 게임 규칙을 설명한다. 처음 가는 지역의 물건이 비싼 이유는 새 지역 시료가 필요해서이고, 같은 물건을
    반복해서 보내면 값이 떨어지는 이유는 그 시료가 이미 충분해서다.
  - 이야기가 진행되면 요청이 구체적으로 바뀐다 (예: "기준일 밤 열려 있던 창문의 커튼", "옥상 물 저장소의 물").
    이런 것은 임무로 온다 (9장). 데드 드롭과 이어진다.
- **운석 파편.** 기준일 밤 떨어진 '이상한 돌 조각'. 캡스톤을 여는 열쇠다. 루팅에는 섞지 않고 **낙하 지점** 세 곳에서만
  줍는다. 낙하 지점은 첫 캐릭터의 시작 위치 둘레 고리 안에 정하고, 그을린 땅과 돌 타일로 눈에 보인다. 지점마다 종류가 다른
  파편 하나(석질·철질·석철질)가 있다. 납품 상자로 연구팀에 보내면 그 종류의 캡스톤이 열리고, 연구팀 메모가 온다. 찾아가는
  것 자체가 원정 목적지가 된다. 지점 목록은 한 번 정해 전역 modData에 둔다. 실물은 그 칸이 든 청크가 불러질 때 놓는다 (Lua `LoadChunk`, 12장 '성능 규칙').

## 4. 핵심 순환

```text
파밍 (첫 발견, 건물 털이)
  → 아지트로 운반
  → 분해 / 납품 상자에 담아 헬기로 납품
  → 크레딧 · 신뢰도
  → 강화 혈청 (강화 포인트)
  → 강화 트리, 상점 개방, 개량 장비와 기계 부품
  → 더 멀리, 더 많이 파밍
```

## 5. 자원

| 자원 | 성격 | 얻는 법 | 쓰는 곳 |
| --- | --- | --- | --- |
| 크레딧 | 쓰면 줄어든다 | 납품 상자로 헬기 납품 | 상점 구매 |
| 신뢰도 | 줄지 않는 누적치 | 지금까지 납품한 총량 | 단계가 오르면 상점이 열린다 |
| 트리 포인트 | 쓰면 줄어든다 | 상점에서 산 트리별 강화 혈청을 투여 | 그 트리에만 |
| 공용 포인트 | 쓰면 줄어든다 | 공용 강화 혈청을 투여. 크레딧으로 못 사고 신뢰도 단계와 도감 이정표로만 받는다 | 아무 트리 |

- 모든 보상은 크레딧으로 모인다. 트리 포인트는 크레딧으로 그 트리의 강화 혈청을 사서 얻는다.
- 공용 포인트만 길이 다르다: 신뢰도 단계(2단계부터, 6단계 뒤에는 매 단계)와 도감 이정표에서 무전 보상으로 공용 강화 혈청이 온다. 드물어서 아껴 쓰는 자원이다.
- 한 번 납품하면 크레딧과 신뢰도가 함께 쌓인다. 따로 벌게 하면 할 일이 복잡해진다.
- 세 자원이 어디서 생기고 어디에 쓰이는지를 화면 한 곳에서 보여 준다 (상점 화면 위쪽에 신뢰도 막대와 다음 단계에서
  열리는 품목).

## 6. 얻는 방법

### 도감 (첫 발견)

- 아이템 종류를 처음 손에 넣으면 도감에 기록하고 크레딧 보너스를 쌓는다. 보너스는 다음 헬기 정산 때 들어온다
  (연구팀이 발견 보고를 받는 설정).
- 카테고리를 일정 비율 채우면 추가 보너스를 준다 (예: 총기 20종 중 15종, 희귀 잡지 전부).
- 도감은 '아이템 종류를 처음 손에 넣는 시점'만 기준으로 한다. 같은 종류를 옮겨 담아도 한 번만 친다.
  `OnFillContainer`는 도감에 쓰지 않는다. 이 이벤트는 용기를 열 때가 아니라 칸이 처음 불러질 때 아직 안 뒤진 용기에서 난다.
  임무 아이템 주입과 털이 기록에만 쓴다.

### 건물 털이

- 한 건물의 용기를 모두 뒤지면 크레딧 보너스를 준다. 다음 건물, 다음 마을로 가게 만든다.

### 분해

- 아지트의 분해 설비에서만 할 수 있다. 실어 와야 하므로 다람쥐 순환이 강해진다.
- 분해하면 작고 가벼운 **시료 묶음**이 나온다. 부피 대비 값이 높아서 납품 상자(기본 용량 50)에 더 많은 값을 담을 수
  있다. 크레딧은 납품 정산으로만 들어온다.
- 다 쓴 배터리도 갈 수 있다. 되살리는 대신 시료 → 크레딧 → 상점 배터리로 돈다.
- 시료 묶음은 상하지 않는다. 분해해서 크게 쌓아 두는 물건이라 기한이 있으면 관리 스트레스만 된다.
- 같은 종류를 반복해서 갈수록 얻는 양이 줄어든다. 가장 흔한 잡템 하나만 쌓아 두고 가는 것이 최적이 되지 않게 한다.
- 처음 갈아 본 종류에는 보너스를 준다 (도감과 합친다).
- 갈 수 있는 범위는 잡템 계열에서 넓게 잡는다. 음식은 넣는다 (썩은 음식은 프로판 정제기와 나눠 쓴다). 탄약은 생존 자원이라 뺀다.

### 납품

- 헬기가 내려올 빈터에 설치한 납품 상자에 물건과 시료를 담아 밀봉하면, 헬기가 투하하면서 가져가고 그때 크레딧과 신뢰도로 바뀐다
  (9장 '거래 방식').

### 좀비 처치

- 마리 수가 아니라 이정표로 크레딧 보너스를 준다 (100, 500, 1000...).

### 좀비 시료 (2026-10-15)

- 방금 죽은 좀비 시체에서 조직 시료를 채취해 납품한다. 연구팀이 감염 자체를 연구하는 몫이다. 처치가 이정표 보너스 말고도
  신뢰도로 이어진다.
- **채취:** 시체 우클릭 메뉴로 한다. 시체 하나에 한 번이고, 죽은 지 얼마 안 된 시체만 된다 (백골, 오래된 시체는 안 됨).
- **등급:** 채취할 때마다 확률로 정한다. 일반 조직, 감염 조직, 신경 조직, 이상 조직의 넷이고, 위로 갈수록 드물고 값지다.
  무게는 모두 같다. 가끔 드문 등급이 나오는 재미가 있다.
- **상하지 않는다.** 연구팀 도구에 밀봉 용기가 딸려 있다는 설정이다. 기한을 두면 관리 스트레스만 된다 (시료 묶음과 같다).
- **한 편 상한과 옷차림 보너스는 두지 않는다.** 시체를 많이 채취해야 상자가 차니, 그 노동이 곧 제동이다.
- **도구:** 우리 아이템 둘이다. 바닐라 메스와 핀셋은 쓰지 않는다 (바닐라 핀셋은 흔해서 정밀 채취가 처음부터 열린다).
  - **채취용 메스:** 손에 들고 있으면 메뉴에 '빠른 채취'가 나온다. 첫 보급 상자에 들어 있고, 1단계 상점에서도 싸게 판다.
  - **정밀 핀셋:** 인벤토리 어디에 있든 된다. 3단계 상점에서만 판다. 핀셋을 한 번이라도 받은 캐릭터에게는 메뉴에
    '정밀 채취'도 나온다 (받을 때 캐릭터에 표시를 해 두고, 메뉴는 그 표시만 본다). 누를 때 인벤토리에서 핀셋을 한 번
    찾고, 없으면 머리 위 문구로 알리고 아무것도 하지 않는다.
  - **정밀 채취:** 시간이 두 배쯤 걸리는 대신 상위 등급 확률이 오른다. 좀비가 몰려오면 빠르게, 안전하면 정밀하게
    고른다. 핀셋을 얻은 뒤에도 빠른 채취가 쓸모 있다.
- 수치는 [수치 문서](NUMBERS.md) 4장.

## 7. 강화 트리

이 모드의 성장 요소는 **강화**라고 부른다. 한국어판 게임에서 트레잇을 '특성'으로 번역해서, 같은 이름을 쓰면
헷갈린다. 강화 혈청 → 강화 포인트 → 강화 트리로 이름이 이어진다.

강화는 강화 혈청으로 얻으므로 **캐릭터 자신의 능력**(몸, 감각, 몸에 밴 요령)만 둔다. 헬기, 상점, 아지트 설비,
장비처럼 연구팀의 지원에서 나오는 효과는 신뢰도 보상이 맡는다 (9장 '신뢰도 보상').

| 트리 | 역할 | 갈래 |
| --- | --- | --- |
| 정찰 | 남보다 먼저 알기 | 좀비 감각(시야 보정, 육감, 기척 감지와 각 강화), 털이 기록, 경보 읽기 |
| 하중 | 짐과 장비의 부담 | 과적, 자재·가구 무게, 옮기기 속도, 캐릭터 용량, 저장소 용량, 열쇠고리, 장비의 달리기·전투 속도 감소와 불편함 |
| 생존 | 몸이 버티기 | 빠루·자물쇠 따기, 낙법, 혈청 적응, 걷는 속도, 수풀 헤치기, 장비 아끼기, 부위 피로, 감염 저항 |

- 후보는 [강화 후보 모음](IDEAS.md)에 모으고, [정련](REFINE.md)을 거쳐 [트리 초안](TREES.md)에 노드와 점을 정한다.
- 트리 안을 갈래로 나누고, 위 단계는 그 트리 전체에 쓴 포인트로 연다.
- 수색·운반·생존에서 정찰·침입·운반·생존 감각 넷을 거쳐 정찰·하중·생존 셋이 됐다. 운반은 착용 장비의 부담까지 맡으며 하중이 됐다. 인기 모드가 이미 하는 루팅·자물쇠
  노드를 빼면서 침입이 없어졌다. 먹고 자는 스탯은 후반에 풀려 있고 바닐라·특성 모드의 축이라, 생존은 이동, 장비 손상, 부위 피로, 감염 같은
  원정 중의 몸을 맡는다. 아지트와 거래 효과는 신뢰도 보상에 남는다.
- 전투 트리는 두지 않는다. 바닐라 스킬과 겹친다.

### 트리가 열리는 때

- 처음에는 강화가 없다. 상점에서 **강화 혈청**을 사서 처음 투여하는 순간 강화 트리가 열린다. 그 순간이 이 모드의
  첫 '사건'이다.
- 캐릭터 창의 적응 탭도 그때까지 없다. 첫 혈청을 맞으면(적응이 시작되면) 탭이 생기며 깜빡인다. 잠긴 트리를 미리 보여 주지
  않아야 첫 사건이 산다.
- 강화 혈청은 트리마다 따로 있다 (예: 현장 탐지 혈청, 하중 적응 혈청). 그 트리의 첫 혈청이 그 트리를 연다. 트리마다
  여는 순간이 따로 있어 '사건'이 세 번 생긴다.
- 강화 혈청 하나가 그 트리 포인트 하나다. 두 번째부터는 포인트만 준다.
- **골고루 찍게 유도한다 (강제하지 않는다):** 값은 트리마다 따로 오른다. 그래서 가장 덜 찍은 트리의 다음 점이 늘 가장
  싸다. 한 트리에 몰아도 되지만 점점 비싸진다. 고인물이 빌드를 고르는 맛은 남기고, 넓게 키우는 쪽이 이득이 되게 한다.
- 공용 강화 혈청은 아무 트리에나 쓴다. 비싸진 트리의 다음 점이나 캡스톤 직전 한 점을 메우는 데 쓴다.
- 잃어버려도 다시 사면 된다. 분실 대책을 따로 두지 않는다.
- 이름은 치료 혈청과 헷갈리지 않게 '시험 혈청'으로 한다 (CANON W5).
- 가격은 그 트리의 혈청을 살 때마다 오른다 (레벨이 오를수록 경험치가 더 필요한 것과 같은 곡선). 성장의 속도 조절이라 스트레스가
  아니다. 치료 혈청처럼 위기에 쓰는 물건의 값은 올리지 않는다는 원칙과 다르다.

### 규칙

- 위 단계는 같은 트리에 포인트를 일정 이상 써야 열린다. 한 트리에 몰지 나눌지 고민하게 만든다.
- 캡스톤은 수치가 아니라 새 동작이다. 포인트에 더해 그 트리의 운석 파편이 연구팀에 닿아야 열린다. 그 전에는 '???' 윤곽만 보여, 무엇이 여는지와 무엇을 주는지는 파편을 보냈을 때 연구팀 메모로 처음 알게 된다.
- 강화 초기화에는 비용이 든다.

### 2차 연구 (세 캡스톤 이후)

- 세 트리의 캡스톤을 모두 승인하면 **2차 연구판** 하나가 열린다. 설정상으로는 운석 파편 세 종류가 연구팀에 닿아 연구가 한 단계 넘어간 것이다.
- 트리마다 따로 두지 않고 판 하나로 둔다. 만들 것이 하나라 깔끔하고, 세 트리를 다 키우게 하는 최종 목표가 된다 (트리별 혈청과 같은 방향).
- 이미 찍은 트리는 그대로 남는다. 2차 연구판은 그 위에 더하는 판이다.
- 노드는 모두 **무한 반복 강화**다. 후반 포인트가 끝없이 쓰일 곳이다. 예: 계열 무게(계열 하나를 골라 운반 효율 +10%), 장비 적응(불편함 경감 +10%).
  - 효과는 (1 + 합)으로 나누는 식처럼 갈수록 덜 오른다. 0이 되거나 상한에 부딪히지 않고 끝없이 찍을 수 있다.
  - 비용은 단계가 오를수록 늘어난다. 무한하지만 점점 느려진다.
- 어느 트리의 혈청이든 공용 혈청이든 이 판에 쓴다.
- 열리기 전에는 '???'로 윤곽만 보여 준다. 캡스톤 하나를 열 때마다 윤곽 하나가 드러난다.
- 강화를 초기화하면 2차 연구도 되돌아간다. 열린 캡스톤은 그대로 열려 있다 (수치표 6장 '강화 초기화').

### 3차 연구 (나중)

- 2차 연구판에 일정 점(예: 30점)을 쓰고 운석 파편을 하나 더 바치면 열린다. 2차는 끝이 없어 '다 찍기'로 열 수 없다.
- 지붕을 타고 다니는 이동(도약, 수직 도약, 체공 이상 반응 "스카이 잭")을 둔다. 새 동작이라 애니메이션과 지붕 판정 조사가
  먼저이고, 지금 스펙에는 넣지 않는다.

### 바닐라와 역할 나누기

| 체계 | 성격 |
| --- | --- |
| 스킬 | 하면 오른다 |
| 특성 (트레잇) | 태어날 때 정한다 |
| 이 모드의 강화 | 탐험하고 모아서 번다 |

- 감지 계열 강화는 바닐라 트레잇(예민한 청각, 매의 눈)을 수치로 키우지 않는다. 방향 표시, 예감처럼 새로운 형태의
  정보로 만든다. 바닐라 청각 특성은 소리 계열의 반경을 바꾼다.
- **가려진 좀비 버그 수정 (기본 기능, 특성 아님):** B42 그림자식 시야에서 보이는 자리에 선 좀비가 안 그려지는 버그를 고친다.
  Zombie Visibility Fix(워크숍 3814073243, wgetJane)의 방법을 참고하되 코드는 가져오지 않는다 (라이선스 없음).
  - 바닐라가 안 그린 좀비 가운데 지금 시야 원뿔과 시야 거리 안에 있는 것만 플레이어에서 좀비까지 선을 그어 검사한다. 트이면
    바닐라와 똑같이 그린다 (`setTargetAlpha`). 원뿔 밖은 건드리지 않으므로 화면의 그림자와 어긋나지 않는다.
  - 같은 층: 칸보다 정밀한 선(실제 위치, 벽 모서리, 막힌 칸).
  - 바로 위·아래 층 (계단, 트인 계단참, 발코니 아래): 바닐라의 층을 넘는 선 검사(`LosUtil.lineClear`, 시작 층과 끝 층을 따로 받음)를
    쓴다. 막힌 바닥과 천장은 통과하지 않아 층 투시가 없다. 두 층 이상 떨어진 좀비는 보지 않는다 (부분 로딩). 층을 넘는 판정은
    인게임에서 계단 위·아래로 확인한다.
  - 드러난 좀비도 바닐라 발견 판정(`IsoPlayer.TestZombieSpotPlayer`)으로 플레이어를 볼 수 있다. 0.1~0.5초 간격.
  - 샌드박스 옵션, 기본 켬. 그 모드가 켜져 있으면 손을 뗀다.
- 시야 보정 노드는 시야 원뿔 각도만 넓힌다 (TREES). 버그 수정과는 별개다.

## 8. 트리 화면

- 와우식 격자에 노드와 연결선을 그린다. 잠긴 캡스톤까지 보여서 목표가 보이게 한다.
- 화면은 '강화 창'이 아니라 **연구팀의 연구 계획서**로 꾸민다. 노드는 연구 항목, 찍는 것은 '연구 승인'이다.
- 위 노드일수록 이름과 설명을 점점 수상하게 한다 (떡밥).
- 노드 툴팁에 현재 효과, 다음 단계 효과, 열리는 조건을 정확한 수치로 보여 준다.
- 찍기 전에 미리 배치해 보고, 확정 버튼으로 적용한다.
- B42의 UI 크기 설정과 패드 조작에서도 쓸 수 있어야 한다.

## 9. 상점

### 거래 방식

아지트에 고정된 상자에 넣고 기다리는 방식은 사건이 없어서 쓰지 않는다. 거래 자체를 작은 이벤트로 만든다.

| 방식 | 용도 | 흐름 |
| --- | --- | --- |
| 단말 주문 + 헬기 | 일상 거래 | 하나뿐인 납품 상자를 빈터에 설치하고 채워 밀봉한다 → 통신 단말에서 살 것을 주문하고 헬기 호출 → 몇 시간 뒤 헬기가 와서 밀봉된 상자를 가져가고, 같은 자리에 주문한 물건이 든 보급 상자와 비운 납품 상자를 두고 간다 → 호출 간격이 지나야 다시 부를 수 있다 |
| 데드 드롭 | 특별 거래, 이야기 진행 | 이야기 임무의 한 형태. 연구팀이 무전이나 지도 아이템으로 좌표를 준다 → 그 장소에 물건을 두고 오거나 받아 온다. 신뢰도가 오를수록 멀고 위험한 곳 |

### 역할 나누기

| 물건 | 역할 |
| --- | --- |
| 무전기 | 거래에도 이야기에도 쓰지 않는다. 바닐라 원작 방송을 듣는 물건으로만 남는다 |
| 통신 단말 | 연구팀과의 모든 거래 창구. 탭 다섯: 상태(헬기 호출, 신뢰도, 개량, 기록), 상점(혈청 칸 포함), 납품(이번 주 요청 품목과 사정), 임무(수신함 포함), 교신(교신 장면 재생과 기록, SCENES.md 2장) |
| 납품 상자 | 보낼 물건을 담는 상자 |
| 보급 상자 | 연구팀이 보내는 물건과 명세서가 담겨 온다 |

- **통신 단말:** Building Utilities의 설비 제어반처럼 조립해서 설치하는 기계다.
  - 재료는 바닐라 데스크톱 컴퓨터(`Mov_DesktopComputer`)와 아마추어 무선기(`HamRadio1`, `HamRadio2`, 임시 제작형
    `HamRadioMakeShift`)에 전자 부품 등을 더한다.
  - 전기가 있어야 켜진다. 바닐라 전력(전력망, 발전기)만 전제로 하고, Building Utilities가 있으면 그 전력망에 붙는다.
    발전기를 돌려야 연락이 되는 긴장이 생긴다.
  - 발전기처럼 들어서 옮기고 내려놓을 수 있다. 원정 지점의 임시 아지트에 새로 조립하거나, 여분을 만들어 차에 싣고
    다닌다. 무거운 물건이라 하중 트리와 어울린다.
  - 창 하나에 탭 다섯으로 나눈다 (상태, 상점, 납품, 임무, 교신). 수신함은 임무 탭 안에 있다. 교신 탭은 이야기 교신 장면을 재생하고 기록한다. 무전기 우클릭 메뉴나 상자 겉면의
    주문 양식에 우겨 넣지 않아도 되므로 화면 설계가 자유롭다.
  - 처음 조립한 단말은 허접한 모습이다. 신뢰도 2단계에서 50,000 크레딧으로 연구팀 정식 단말을 따로 주문해 새로 설치하면
    연구팀 물건 주문, 특별 의뢰, 운항 지원 신청(개량)이 열린다. 조립 단말은 그대로 쓸 수 있다. 보상이 손에 잡히는 물건으로 온다.
  - 모양은 우리가 직접 그린 타일이다 (12장 '에셋').
- **도착:** 호출하고 몇 시간 뒤(가안 4~6시간)에 온다. 헬기는 낮에만 다닌다. 도착 시각이 밤에 걸리면 다음 날 아침에
  온다. 개량 '야간 투하'를 받으면 밤에도 온다. 단말에 도착 예정 시각을 보여 준다.
- **호출 간격:** 도착 시간과 따로, 한 번 부르면 정해진 시간(가안 3일)이 지나야 다시 부를 수 있다. 개량
  '호출 간격 단축'으로 줄어든다. 단말에 다음 호출 가능 시각을 보여 준다.
- **주문:** 단말에서 고른 주문은 호출한 그 헬기 편에 실려 온다. 주문 없이 납품만 해도 되고, 납품 없이 주문만 해도 된다
  (빈 납품 상자를 빈터에 두고 부른다).
- **결제:** 헬기가 도착하면 먼저 그 편의 납품을 정산하고, 그 크레딧까지 더해 주문 값을 뺀다. 모자라면 살 수 있는
  만큼만 오고, 명세서에 사유가 적혀 온다. 헬기를 부르기 전에 예상 잔액을 보여 준다.
- **새 품목 알림:** 신뢰도 단계가 오르면 단말과 보급 명세서로 "새 품목 추가"를 알린다.
- **시작 꾸러미 (첫 보급):** 첫 헬기 때 캐릭터가 있던 건물 앞 도로, 없으면 가장 가까운 빈터에 납품 상자 하나가 놓인다.
  상자 안에는 다 조립된 통신 단말(무게 12), 조립법 책자, 채취용 메스가 들어 있다. 설명 화면 없이 물건으로 시작 방법을
  알려 준다: 단말을 아지트에 놓고 켜고, 받은 상자를 빈터에 설치해 채우고 밀봉한 뒤 단말로 헬기를 부른다.
  - 단말 완성품을 주는 까닭: 조립에는 전기 기술 3과 데스크톱, 아마추어 무전기, 증폭기가 든다. 전기 기술이 없는 캐릭터도
    시작할 수 있어야 한다. 단말은 여전히 전기가 있어야 켜지고, 무거운 단말을 헬기 소리에 몰려든 좀비 사이에서 들고
    오는 것이 첫 긴장으로 남는다.
  - 책자는 단말을 잃어버렸을 때와 아지트를 여러 곳 둘 때를 위한 것이다. 그때는 지금처럼 전기 기술 3이 필요하다.
  - 바닐라 헬기 설정(기본 '한 번')이 켜져 있으면 그 첫 헬기가 상자를 두고 간다. 헬기 소리가 좀비를 끌어오는 바닐라
    사건 그대로라, 상자를 챙기러 나가는 것이 첫 긴장이 된다.
  - 헬기가 '없음'이면 같은 무렵(7일째)에 헬기 없이 조용히 두고 간다.
  - 헬기가 이미 지나간 뒤에 모드를 넣었으면 다음 날 아침 조용히 두고 간다.
  - 놓인 상자에서 잠깐 연기가 오르고 지도에 표시된다 (보급 상자 '찾기'와 같은 방식, 주우면 표시가 사라진다).
- 단말이 없는 곳에서는 거래도 헬기 호출도 못 한다. 밖에서 필요한 '무엇을 찾을지'는 단말에서 미리 본 이번 주 요청 품목과
  시세가 맡는다.

### 시세

시료와 잡템의 값은 고정이 아니라 날마다 움직인다. 싸게 모아 두었다가 비쌀 때 보내는 판단이 생기고, 쌓아 두는
다람쥐 플레이에 이유가 하나 더 붙는다.

- **계열마다 시세:** 계열(바닐라 `DisplayCategory`를 묶은 것, 트리 문서의 계열 무게와 같은 묶음)마다 시세 지수가 있다.
  날마다 조금씩 오르내리되, 오래 벗어나면 기준값으로 돌아오는 쪽으로 움직인다 (한쪽으로 폭주하지 않게).
- **많이 보내면 내린다:** 한 계열을 많이 보내면 그 계열 시세가 내려가고 시간이 지나면 회복한다. 예전의 '이미 충분'이
  이 움직임이 된다.
- **연구팀 사정:** 이야기 사건이 그 계열의 시세를 끌어올린다. 납품 탭의 '이번 주 사정'에 이유가 뜬다
  ("필터 시료 급히 필요").
- **새 지역 시료:** 처음 가는 지역 시료의 웃돈은 시세와 별개로 붙는다 (설계 문서 3장의 설정).
- **보이게:** 납품 탭의 '이번 주 사정'에 계열별 오늘 지수를 보여 준다 (그래프는 없다). 개량 '내일 시세 방향'을 받으면 오름·내림 표시가 붙는다. 감정가 툴팁과 견적 창도 지금 시세로 계산한다.
- **정산 시점:** 밀봉할 때가 아니라 헬기가 실어 갈 때의 시세로 정산한다. 밀봉해 두고 시세를 기다리는 선택이 생긴다.
  밀봉 상자에는 품목과 수량만 기록한다.
- **되팔기 막기:** 상점에서 산 물건은 납품을 받지 않는다. 사고팔기로 크레딧을 불리는 길을 막는다.

### 현금

- 바닐라 현금(`Money`, 돈 묶음 `MoneyBundle`)은 **1달러 = 100크레딧**으로 바꾼다. 시세가 없다.
- 크레딧은 정수만 쓴다. 소수점이 없다. 1달러를 100으로 두면 환산율 개량(예: +5%)이 붙어도 1달러 = 105크레딧처럼
  정수로 떨어진다.
- 반올림은 헬기 한 편의 정산 합계에서 한 번만 한다. 아이템마다 반올림하면 잡템을 많이 보낼수록 값이 새어 나간다.
- 개량 환산율은 현금에도 붙는다. 거래를 키우면 같은 현금이 더 많은 크레딧이 된다.
- 납품 상자에 넣어 보내면 크레딧이 된다. 돈 묶음은 풀었을 때의 장수만큼 친다.
- 바닐라에서 쓸모없던 현금이 처음으로 모을 이유가 생긴다.

### 헬기와 상자

- **투하 위치 = 납품 상자:** 납품 상자에는 발신기가 달려 있다. 헬기는 신호탄이 아니라 설치된 납품 상자의 발신기를 보고
  날아온다. 다음 거래 위치는 상자를 어디에 두느냐로 정한다.
  - **설치 조건:** 헬기가 내려올 공간이 있어야 한다. 지붕 없는 바깥이고 주변 몇 칸에 건물·나무가 없는 곳에만 납품 상자를
    설치할 수 있다. 설치할 때 칸을 표시해 되는 곳과 안 되는 곳을 보여 준다.
  - **주문만 할 때:** 빈 납품 상자를 설치해 두면 그 자리로 보급 상자가 온다.
  - **위치 추적:** 발신기가 있으므로 상자가 마지막으로 놓였던 자리를 지도 마커와 단말 상태 탭(방향과 거리)으로 보여 준다.
    들고 다니거나 차에 실으면 마지막으로 내려놓은 자리다. 어디 뒀는지 잊어서 잃어버리는 일은 없다.
  - 헬기 소리가 좀비를 끌어들이므로, 아지트에서 일부러 조금 떨어진 빈터로 상자를 들고 가 두는 판단이 생긴다.
- **납품:** 헬기가 투하하면서 그 자리의 밀봉된 납품 상자를 끌어올려 간다.
- **소음:** 헬기 소리로 좀비를 끄는 범위는 샌드박스 옵션으로 연다.
- **납품 상자 (보내는 쪽).** 다람쥐 플레이의 결실을 넘기는 곳이라 받는 상자보다 중요하다. 깜깜이로 넣고
  기다리면 재미가 없다.
  - **상자 하나:** 활성 납품 상자는 플레이어마다 늘 하나뿐이다. 이름을 '상자'로 해서 배낭과 다른 물건임을 바로 알 수
    있게 한다. 상태가 두 가지다.
    - **설치된 납품 상자:** 빈터에 설치하고 그 자리에서 채운다. 바닥에 놓는 보통 상자처럼 동작한다. 용량은 헬기 단계를
      따른다. 납품 가능한 물건만 들어간다. 비어 있을 때는 바닐라 가구처럼 들어서 다른 빈터로 옮길 수 있다.
      차를 옆에 대고 '한꺼번에 담기'로 채우는 것이 기본 흐름이다.
    - **밀봉(대기) 상태:** 밀봉하면 그 자리에 고정되어 헬기를 기다린다. 열거나 들어 옮길 수 없다.
    - 밀봉하는 순간 품목과 수량을 기록하고 실제 아이템은 지운다. 그 뒤로 음식이 상하지 않는다. 값은 헬기가
      실어 갈 때의 시세로 매긴다.
    - **부서지면:** 대망치나 불로 밀봉된 상자가 부서지면 내용물은 날아간다. 활성 상자였으면 재발급한다.
    - 밀봉은 되돌릴 수 없다. 밀봉 전에 최종 견적을 보여 주고 확인을 받는다. 되돌리기를 허용하면 아이템 상태(내구도,
      액체 등)를 전부 저장했다가 복원해야 해서 복잡해진다.
    - 가방처럼 메는 용기가 아니므로 일반 파밍용 초대형 가방으로 쓰는 꼼수가 원천적으로 없다.
  - **개량 '상자 용량' = 상자 용량:** 개량으로 단계를 사면 납품 상자의 용량이 커진다. 상자를 바꾸거나 더 받을 필요가 없다.
    바닐라 용기 상한(100)은 확장 API로 걷어낸다. 신뢰도 단계는 다음 단계를 신청할 수 있게 열어 줄 뿐이다.

    | 신청할 수 있게 되는 단계 | 용량 |
    | --- | --- |
    | 처음 | 50 |
    | 신뢰도 3단계 | 100 |
    | 신뢰도 5단계 | 200 |
    | 신뢰도 6단계 | 250 |
    | 신뢰도 7단계 | 300 |
    | 신뢰도 8단계 (이관) | 350 |
    | 신뢰도 9단계부터 단계마다 | +50씩 (단계 간격이 점점 벌어짐) |

    도착 시간 단축, 호출 간격 단축, 야간 투하도 각각 따로 신청하는 개량이다.
  - **되돌려 받기:** 헬기는 밀봉된 상자를 가져가고 같은 편에 비운 납품 상자를 그 자리에 다시 내려 준다. 따로 만들거나
    사지 않는다.
  - **재발급:** 상자가 부서졌거나 원정지처럼 먼 곳에서 거래하고 싶으면 단말에서 새 상자를 요청한다. 헬기 호출 한 번으로
    치므로 호출 간격이 걸린다. 새 상자는 단말 근처 빈터에 떨어진다 (첫 보급과 같은 방식).
    - **재발급 비용:** 크레딧을 낸다 (10,000, 수치표 8장). 납품 때 되돌려 받는 빈 상자는 공짜다.
    - **크레딧이 모자라면** 그래도 보내 주고 잔액이 마이너스가 된다. 빚은 다음 납품 정산에서 먼저 갚고, 빚이 있는 동안
      상점 주문은 막는다. 상자가 없어 크레딧을 벌 수 없는 막힘을 피한다. '0이면 공짜'로 하면 주문으로 잔액을 0 근처로
      비운 뒤 공짜로 받는 길이 생긴다.
    - 새 상자가 활성 상자가 되고, 옛 상자는 '이전 상자'가 된다.
    - **밀봉된 이전 상자:** 다음 헬기가 활성 상자와 함께 모두 실어 간다. 떨어져 있어도 된다. 주문한 물건과 되돌려
      주는 빈 상자는 활성 상자 자리에만 온다.
    - **밀봉 전 이전 상자:** 보통 상자처럼 계속 쓴다. 밀봉하면 위처럼 실어 간다. 재발급을 거듭해 이전 상자를 보관함으로
      모아도 막지 않는다. 재발급마다 크레딧과 호출 간격, 헬기 소음을 치르는 선택이고, 연구팀 보관함 같은 보상으로 용량은 어차피
      넉넉해진다.
    - 되돌려 받는 상자는 늘 하나다. 이전 상자는 실어 가면 끝이다. 상자마다 되돌려 주면 재발급 몇 번으로 활성 상자가
      영구히 늘어 헬기 단계(용량)가 의미를 잃는다.
  - **헬기를 부르려면** 활성 상자가 빈터에 설치되어 있어야 한다 (밀봉했든 비었든). 보급 상자가 떨어질 자리다.
  - **감정가 미리 보기:** 아이템 툴팁에 연구팀 감정가를 표시한다. 상자를 열면 옆에 견적 창이 붙어 아이템별 값과
    합계를 보여 준다. 값은 지금 시세다. 각 아이템에 표시를 단다: '새 지역 시료'(웃돈), '시세 높음/낮음', '받지 않음'.
  - **이번 주 요청 품목:** 단말에서 주마다 바뀌는 요청 목록을 받는다. 목록의 물건은 시세 대신 흔한 정도로 정한
    개당 고정 단가(흔함 600, 보통 1,500, 드묾 4,000)로 쳐주고, 품목마다 주 수량(10 / 5 / 3)이 있다. 다 채우면 신뢰도 보너스가 붙는다.
    수량을 넘긴 개수는 평소 감정가로 받는다. 계열 시세는 건드리지 않는다. 견적 창과 영수증에 요청 줄을 따로
    적는다. 단가 배율은 개량 '요청 단가'로 오른다. 파밍 목표가 생기고 매주 찾는 것이 달라진다.
  - **세 갈래:** 납품 물건은 일반, 요청, 임무로 나뉜다.

    | 갈래 | 무엇 | 값 | 기한 |
    | --- | --- | --- | --- |
    | 일반 | 납품 가능한 모든 물건 | 실어 갈 때의 시세 | 없음 |
    | 요청 | 이번 주 요청 목록에 오른 바닐라 물건 | 고정 단가 (수량 안) | 그 주 |
    | 임무 | 임무마다 새로 생기는 이 모드의 물건 | 정해진 보상 (크레딧 + 신뢰도) | 임무 기한 |

  - **임무:**
    - 단말에 임무가 한 번에 하나 뜬다. 끝나거나 기한이 지나면 며칠 뒤 다음 임무가 온다.
    - 임무가 생길 때 통신 단말에서 일정 거리대 안의 건물 하나를 무작위로 골라, 그 안 용기에 임무 아이템을 둔다. 가 본
      건물도 고른다. 늘 안 가 본 곳만 주면 스트레스가 되고 찾기도 무거워진다. 거리대는 신뢰도 단계가 오를수록 멀어져서
      안 가 본 지역은 자연스럽게 섞인다.
    - 거리대의 안쪽 끝이 있어서 아지트 건물에는 생기지 않는다.
    - 지도에는 건물이 아니라 그 일대를 원으로 표시한다. 임무 하나에 표시 하나이고 임무가 끝나면 지운다. 쌓이지 않는다.
    - 기한(가안 7일)은 밀봉 시점으로 따진다. 호출 간격 때문에 헬기를 기다리다 기한을 놓치는 일이 없게 한다.
    - 기한이 지나면 임무와 지도 표시가 사라진다. 이미 주운 임무 아이템은 일반 물건(시료)으로 낮게 쳐준다. 벌점은 없다.
    - **이야기 임무:** 이야기가 진행되면 정해진 장소의 임무가 섞인다 (설정집 4장의 단계별 이야기 임무). 데드
      드롭은 이야기 임무의 한 형태다.
    - 고인물 기준: 매번 다른 건물이라 지도를 다 외워도 새 목적지가 생긴다. 원정을 떠날 이유가 된다.
    - **좀비 임무 (2026-10-15):** 일반 임무 순환에 두 종류를 더한다. 단말을 켠 1단계부터 나온다. 기한, 실패, 보상 규칙은 다른
      일반 임무와 같다. 장소는 건물이 아니라 거리대 안의 빈터 한 곳이고, 지도에는 같은 원으로 표시한다.
      - **구역 정리:** 원 안에 연구팀이 지목한 좀비 무리(우리 옷차림)가 있다. 모두 처치하면 끝난다. 차로 치든 불에 타든,
        어디서 죽든 센다. 이 무리의 시체에서는 보통 등급 시료가 나온다.
      - **표적 시료:** 원 안에 표적 좀비 몇 마리(우리 옷차림)가 섞여 있다. 그 시체에서만 '임무 시료'가 나온다. 임무
        시료에는 어느 임무 것인지 적혀 있고, 다 모아 납품 상자로 보내면 끝난다. 임무 시료는 빠른 채취로도 나온다.
      - **나타나기:** 플레이어가 원에 다가와 그 칸들이 불러지면, 아직 보이지 않는 거리에서 원 안에 나타난다. 칸은 막히지
        않고 바닥이 있으며 이어진 곳에서 고른다 (벽 속, 물, 계단은 뺀다).
      - **머물기:** 무리는 할 일 없이 배회할 때 원 밖으로 나가지 않고, 먼 곳의 소리(다른 곳의 경보, 사이렌)에 끌려 나가지
        않는다. 플레이어가 낸 소리와 원 근처의 소리에는 바닐라대로 반응한다. 싸우다 원 밖까지 쫓아오는 것은 막지 않는다.
      - **떠나면:** 플레이어가 떠나 그 칸이 내려가면 남은 무리는 지운다 (가상 좀비로 남기지 않는다). 다시 오면 남은 수만큼
        다시 나타난다. 원 밖으로 나가 따로 남은 무리는 임무가 끝나거나 기한이 지날 때 지운다.
  - **한꺼번에 담기:** 아지트 보관함이나 차량 트렁크에서 '받는 것만 담기'로 납품 가능한 물건을 한 번에 옮긴다.
    잡템을 하나씩 옮기는 노동을 없앤다.
  - **밀봉 확인:** 밀봉 전에 최종 견적과 함께 '받지 않음' 물건이 섞여 있지 않은지 보여 준다. 실수로 귀한 물건이
    실려 가는 일을 막는다.
  - **영수증:** 헬기가 가져간 뒤 다음 보급 명세서로 품목별 정산 내역과 연구팀의 한마디가 오고, 단말 상태 탭에는 마지막 정산 한 줄이 남는다
    ("커튼 시료 매우 유용", "통조림은 더 필요 없음"). 무엇이 값진지를 플레이하며 배운다.
- **보급 상자 (받는 쪽).** 그냥 용기가 아니라 '받는 순간'이 즐거워야 한다.
  - **생김새:** 연구팀 표식과 스텐실 문구가 찍힌 군용 보급 상자. 한눈에 '연구팀이 보낸 것'으로 알아보게 한다.
    우리가 직접 그린다 (12장 '에셋').
  - **봉인 해제:** 열려면 시간이 걸리는 '봉인 해제' 행동을 거친다. 빠루가 있으면 더 빠르다. 걸쇠 소리와 함께 열린다.
  - **보급 명세서:** 상자마다 연구팀의 짧은 메모가 든 명세서가 들어 있다. 주문 내역과 함께 한두 줄의 근황이나
    떡밥이 적혀 있다. 이야기는 무전과 이 명세서로 흘러간다.
  - **덤:** 가끔 주문하지 않은 작은 물건이 들어 있다 ("필요할 것 같아 동봉함"). 좋은 쪽의 놀라움만 둔다.
  - **비운 상자:** 연 상자는 꺼내기만 되고 넣을 수 없다 (헬기마다 하나씩 오는 상자가 공짜 보관함이 되지 않게). 다 비우면
    부서지며 그 자리에 판자 3개와 못 6개를 남긴다.
  - **찾기:** 내려앉은 상자에서 잠깐 연기가 오르고 지도에 표시된다.
- 연구 거점(지도의 실제 장소)을 직접 찾아가는 거래는 이야기 후반의 특별한 장소로만 쓴다. 아지트 밖으로 나르는
  방향이라 주력 방식으로는 다람쥐 순환과 맞지 않는다.

### 품목과 단계

신뢰도 단계가 오르면 품목이 열리고 구매 한도가 풀린다. 가격은 고정이거나 완만하게 오른다. 쓸 때마다 값이 오르는 방식은
강화 혈청에만 쓴다 (끝없는 크레딧 소비처). 가방·차 개조 키트는 값이 고정이다.

| 종류 | 예시 | 열리는 조건 |
| --- | --- | --- |
| 연구팀 장비, 야전 공구 | 연구팀 기름통·용접 토치·허리 가방, 바닐라 도구보다 조금 가볍고 오래가는 야전 공구 45종. 등급 없이 한 가지씩 팔고, 더 키우는 것은 개조 키트가 맡는다 | 신뢰도 단계 |
| 기계 부품 | 모터, 날, 촉매·필터, 방음 덮개. 구형·일반·신형 등급, 쓰면 닳는다 (차 부품과 같은 방식) | 신뢰도 단계 |
| 강화 혈청 (트리별) | 그 트리 포인트 1. 처음 투여하면 그 트리가 열린다. 트리마다 따로, 살 때마다 값이 오른다 | 첫 교신부터 |
| 혈청 칸 (감염 치료) | 치료 혈청, 감염 역전제, 감염 지연제 2종, 감염 검사 키트 | 치료 혈청은 5단계, 나머지는 처음(1단계)부터. 구매 한도 없음 |

- 후반에 바닥나는 소모 자원(프로판, 휘발유, 배터리, 발전기 부품)을 다시 얻는 길을 **비싸게** 연다. 싸면 후반 자원
  관리의 긴장이 사라진다.
- 기계 부품은 바닐라 차 부품처럼 기계마다 정해진 자리에 달고 떼는 실물 부품이다. 세계관에 맞게 모듈 슬롯은 쓰지 않는다.
- 이름은 설정에 맞게 짓는다 (연구팀 기름통, 야전 망치).

### 구매 한도

- 혈청 칸의 물건(치료 혈청, 감염 역전제, 감염 지연제, 감염 검사 키트)에는 구매 간격도 한 번에 사는 수의 제한도 없다.
  공급은 헬기 호출 간격과 납품 상자가 막는다. 상점 할인은 혈청 칸에 걸리지 않고, 빚으로는 살 수 없다.
- **유통 기한:** 치료 혈청은 보급 상자로 받은 때부터 7일(가안)이 지나면 효과가 없다. 쌓아 둘 수 없으니 좀비 앞에서의 긴장이
  남는다. 기한은 아이템 modData의 발급 시각으로 쓸 때만 확인하고, 툴팁에 남은 기간을 보여 준다. 구매 시각은 따로 기록하지 않는다.
- 설정상으로는 연구팀이 생존자마다 배정량을 관리한다.
- 발급받은 본인에게만 듣는다. 멀티에서 한 사람에게 몰아주는 것을 막는다.

### 신뢰도 보상

몸과 상관없는 효과는 연구팀의 지원이므로 신뢰도 단계가 오를 때 열린다. 이전에 아지트·거래 트리에 있던 효과다.
수치를 올리는 효과는 크레딧으로 사는 개량(운항 지원 신청)이고, 신뢰도 단계는 다음 단계를 신청할 수 있게 열어 줄 뿐이다.
신청은 정식 단말에서 하고, 결제와 적용은 다음 헬기 정산 때다.

| 분야 | 보상 예시 |
| --- | --- |
| 헬기 | 상자 용량, 도착 시간 단축, 호출 간격 단축, 야간 투하 (모두 개량) |
| 거래 | 납품 크레딧 환산율, 상점 할인, 요청 품목 수, 요청 단가, 체감 완화, 내일 시세 방향 (개량). 신뢰도 획득량(신뢰도 가속)은 개량이 아니라 신뢰도 보상으로 남는다 |
| 상점 | 새 품목 개방 |
| 아지트 지원 | 정식 단말(2단계, 50,000), 연구팀 보관함(큰 용량), 대형 빗물 저장소, 설치형 미끼, 대량 분해기, 재단기, 프로판·오일 정제기, 목재 절단기 |
| 장비 | 연구팀 배낭(최고 단계), 확장·경량·보강·엔진 튜닝 키트(6단계, 샌드박스로 끌 수 있음. 가방, 연구팀 장비, 야전 공구, 차를 키우고, 값은 고정) |

- 아지트 지원과 장비는 대부분 '받을 수 있게 되는 물건'이다. 단계가 오르면 상점에 실리거나 보급 상자로 한 번 지급된다.
- 신뢰도는 5단계(접수, 분류, 대조, 지정, 전담)와 그 뒤 6단계, 7단계, 8단계(이관)로 나누고 9단계부터 끝없이 이어진다. 단계마다 주 이야기 임무가 하나 있다
  (설정집 4장). 5단계 뒤의 단계는 코드에서 아직 이정표라 부르지만, 화면에서는 단계로 부른다.
- **결말은 '이관'이다.** 8단계에서 작전이 다른 부서로 넘어간다. 호출부호가 바뀌고 이관 문서(채집점 상태표 사본,
  미해결 사항 목록)가 온다. 거래와 수치는 그대로 이어지고, 이관 뒤에도 9단계부터 단계마다 이야기 임무와 계약 임무가 나온다
  (설정집 5장).
- 최고 단계 뒤에도 신뢰도는 계속 쌓이므로, 9단계부터 단계마다 상자 용량 +50 개량 단계가 하나 열리는 끝없는 보상을 둔다. 단계 간격은
  점점 벌어진다.

## 10. 감염

| 수단 | 효과 | 얻는 곳 |
| --- | --- | --- |
| 감염 지연제 (7일, 1일) | 먹는 동안 감염 진행이 멈춘다. 치료가 아니다. 감염된 채 좀비에게 새로 다치면 약효가 사라진다. | 상점 혈청 칸. 구매 간격과 개수 제한이 없고, 기한이 없어 쌓아 둘 수 있다. |
| 감염 역전제 | 감염 진행을 0으로 되돌린다. 감염은 남아 지연제는 계속 필요하다. | 상점 혈청 칸. |
| 감염 검사 키트 | 쓰면 감염 여부가 바로 나온다. | 상점 혈청 칸. |
| 치료 혈청 | 감염을 치료한다. | 상점 혈청 칸. 유통 기한이 지나면 효과가 없다. |
| 생존 트리 | 감염 저항(병, 시체 악취), 감염 저항 강화(긁힘·찢김 감염 확률 감소, 7일에 한 번 물림 버티기) | 강화 ([트리 초안](TREES.md)) |

- 감염 진행 지연은 강화가 아니라 아이템이 맡는다.
- 감염된 동안, 그리고 좀비 상처 뒤 검사 전에는 그 편 납품 크레딧에서 감염 처리 수수료 30%를 뗀다. 값과 셈은 [수치표](NUMBERS.md) 10장.
- 지연제는 쌓아 두는 자원이고, 치료 혈청은 받은 뒤 7일 안에 쓰는 자원이다. 혈청을 쌓을 수 없어 좀비 앞의 긴장이 남는다.

## 11. 샌드박스 옵션

밸런스 숫자는 모드에 두고, 옵션은 그 숫자에 곱하는 배율로만 둔다 (1 = 모드 기본). 세이브는 만든 날의 옵션 값을 그대로 갖고 있어서, 숫자를 옵션에 두면 밸런스 패치가 기존 세이브에 닿지 않는다.

- 강화 혈청 기본 가격과 오르는 비율, 강화 효과 크기
- 공용 강화 혈청을 주는 간격 (6단계부터 단계마다)
- 도감·건물 털이·처치 이정표의 크레딧 보너스 배율
- 크레딧 환산 배율, 신뢰도 단계별 필요량
- 상점 가격 배율
- 치료 혈청 값과 유통 기한 기본값 (지연제는 아이템마다 7일, 1일로 고정)
- 납품 상자 재발급 비용, 헬기 도착 시간, 호출 간격 기본값
- 가방·차 개조 키트 판매 켜기 (기본 켬)
- 요청 단가 배율, 임무 기한과 다음 임무까지의 간격
- 분해 반복 시 감소율

## 12. 구현 메모

B42 API 이름은 만들기 전에 실제 게임 코드로 다시 확인한다.

| 기능 | 방법 |
| --- | --- |
| 첫 발견 | 아이템 종류를 처음 손에 넣는 시점(인벤토리에 들어올 때). `OnFillContainer`는 쓰지 않는다 |
| 처치 이정표 | `OnZombieDead` |
| 저장 | 플레이어 modData (포인트, 도감, 강화, 크레딧, 신뢰도) |
| 트리와 상점 화면 | ISUI (ISPanel, 버튼, 텍스처, 선 그리기) |
| 분해 | 설비 우클릭 메뉴 + 시간이 걸리는 행동(timed action) |
| 첫 보급 | 바닐라 헬기(`zombie.iso.Helicopter`)가 처음 켜질 때 표적 캐릭터 근처의 건물 앞 도로·빈터에 납품 상자를 놓는다. 헬기 설정이 '없음'(샌드박스 `Helicopter`)이면 7일째, 모드를 늦게 넣었으면 다음 날. 헬기 이벤트 API가 생기기 전에는 Lua 폴링판으로 한다: 바닐라 헬기가 날 수 있는 창(헬기 날 창)을 시각으로 따져 두었다가 그 창이 지나면 투하하고, 투하한 뒤에는 폴링을 끈다. 이후 API 상태 이벤트(`OnPZExtHelicopter`)가 생기면 실제 헬기 시각에 맞추는 판으로 바꾼다. '헬기 없음 7일째'와 '늦은 도입' 경로는 폴링판 그대로 둔다 |
| 통신 단말 | 조립 레시피로 만드는 설치형 오브젝트 (들어 옮길 수 있음). 전기가 있을 때만 켜짐. 우클릭 → 단말 창 (ISUI, 탭 다섯). 처음엔 데스크톱과 아마추어 무전기를 엮은 허접한 조립 단말이다. 정식 단말은 신뢰도 2단계부터 상점 기계 부문(50,000)에서 따로 주문해 새로 설치하는 아이템(`FieldTerminal`)이고, 놓으면 오브젝트에 modData `OA_Upgraded`가 붙어 연구팀 물건 주문, 특별 의뢰, 운항 지원 신청이 열린다. 조립 단말은 그대로 쓸 수 있다. 판정은 쓰는 단말의 `OA_Upgraded`를 서버에서 다시 본다 (들면 정식 단말 아이템 `FieldTerminal`이 된다). 처음 놓은 정식 단말이 레코드의 회선(`heli.line`)을 연다 |
| 헬기 호출 | 통신 단말 창 → 호출. 도착 시각을 정해 저장 (밤에 걸리면 다음 날 아침, 야간 투하 개량이 있으면 그대로) |
| 상점 화면 | 통신 단말 창의 상점 탭. 주문은 플레이어 modData에 호출한 헬기 편으로 기록 |
| 시세 | 계열별 지수를 게임 날짜마다 갱신해 저장 (평균으로 돌아오는 무작위 움직임 + 납품량에 따른 하락과 회복 + 사건) |
| 주문 대기열 | modData에 주문 내용과 도착 시각 저장 |
| 헬기 투하 | 애니메이션은 만들지 않는다. 바닐라 헬기 이벤트도 소리로만 표현된다. 연출: (1) 헬기 소리가 다가왔다 멀어짐 + 소리가 가장 클 때 투하 지점에 상자 생성 + 좀비를 끄는 소음 + 무전 "투하 완료". 상자는 우리 타일. (2) 낙하산 달린 상자 그림에서 1~2초 뒤 내려앉은 상자 그림으로 바꾸기 (정지 그림 두 장). (3) 나중에 다듬기: 땅 위를 지나가는 헬기 그림자. 3D 헬기 모델은 만들지 않는다 |
| 납품 상자 | 바닥에 놓는 용기 오브젝트 (용량은 헬기 단계, 아이템 허용 조건으로 납품 가능 물건만). 상자 ID를 modData에 두고 플레이어의 활성 ID와 맞춰 본다. 다르면 이전 상자로 다룬다 (정산 때 되돌려 주지 않을 뿐, 훑지 않는다) |
| 밀봉 | 품목 기록을 상자 오브젝트가 아니라 플레이어 전역 modData에 상자 ID별로 둔다. 헬기가 올 때 상자가 있는 칸이 안 불러져 있을 수 있어서다. 밀봉된 상자는 열기·들기 메뉴를 막는다. 부서짐은 오브젝트 제거 이벤트로 받아 기록을 지운다 |
| 납품 정산 | 투하 시점에 밀봉된 모든 상자(활성 + 이전)의 전역 기록으로 정산한다. 실물 상자 제거와 보급 상자·빈 상자 생성은 그 칸이 불러져 있으면 바로, 아니면 그 칸이 든 청크가 불러질 때 한다 (아래 '성능 규칙'의 `LoadChunk` 대기 표). 기록된 품목을 그때의 시세로 값을 매겨 크레딧과 신뢰도 적립. 현금은 1:1 |
| 투하 위치 | 설치된 납품 상자의 위치. 설치할 때 지붕 없음(`IsoGridSquare.isOutside`)과 주변 칸의 건물·나무를 검사 |
| 감정가 표시 | 아이템 툴팁에 한 줄 추가(인벤토리 툴팁 확장) + 납품 상자를 열 때 붙는 견적 창 |
| 한꺼번에 담기 | 납품 상자 우클릭 → 근처 용기와 차량 트렁크에서 납품 가능한 아이템을 골라 옮기는 행동 |
| 이번 주 요청 품목 | 게임 날짜 기준 주마다 목록을 다시 뽑아 저장 |
| 이야기 장치 | [설정집](LORE.md) 7장의 장치를 모두 넣는다: 임무 탭 안의 수신함, 이야기 임무 우선 배정과 장소 후보, 부속 문서, 선택형·교환형·현장 거래형 임무와 현장용 호출 장치, 현장 조건, 계열 일시 '받지 않음', 큰 운석 거절, 명세서 비고 순서 풀과 구판 서식, 무전 인사 변화, 별도 주파수, 채집점 번호, 환각 연출, 낙하지 소품, 이관 처리. 구현이 막히는 것만 그때 다시 판단한다 |
| 임무 아이템 배치 | 건물은 단말에서의 거리대로 `BuildingDef` 하나를 무작위로 고른다 (방문 여부는 보지 않는다). 그 건물 용기가 아직 채워지지 않았으면 `OnFillContainer`에서 넣고, 이미 채워졌으면 그 청크가 불러질 때 넣는다 (아래 '성능 규칙'의 `LoadChunk` 대기 표). `OnFillContainer`는 칸이 처음 불러질 때 미탐색 용기에서 나므로 용기를 열 때를 기다리지 않는다. 훑지 않는다 |
| 좀비 시료 | 시체(`IsoDeadBody`) 우클릭 메뉴. 메스는 손 두 칸만 보고, 정밀 채취는 캐릭터 표시만 본다 (메뉴를 열 때 인벤토리를 뒤지지 않는다). 채취한 시체는 시체 modData에 표시한다. 신선도는 시체의 죽은 시각으로 따진다 |
| 좀비 임무 | 무리는 바닐라 옷차림(지역 정리 `Generic01`, 표적 `HospitalPatient`)으로 나타나게 하고, PZ Extension API의 좀비 표식(`zombies.mark`, 키는 임무 id)으로 알아본다. 옷차림은 표식이 될 수 없다: 게임이 맵 좀비에게 모드 옷차림까지 무작위로 입힌다. 표식은 좀비 modData(시체로 복사된다)와 월드 전역 ModData(좀비의 persistentId 기준, 가상화·세이브를 거쳐도 남는다)에 함께 있다. 처치는 `OnZombieDead`에서 `markOf`로 센다. 표적 시료도 시체의 표식으로 가린다. 임무가 끝나면 `forget`으로 그 키를 지운다. `zombies.hold` 하나가 그 키의 좀비에 세 가지를 맡는다: 배회 목줄(`ZombieIdleState`의 길찾기를 원 안으로 당김, 원 반경 + 20칸 안에 있는 동안), 소리 거르기(`WorldSoundManager.getBiggestSoundZomb`가 고르는 소리에서 원 밖 먼 소리를 뺀다, 플레이어 소리는 늘 남긴다), 내릴 때 지우기(`ZombiePopulationManager.removeChunkFromWorld`에서 가상화하지 않고 지운다). 모드 내용이 없는 일반 기능이다. 지역이 로드되면 한 번 더 기다렸다가 센다: 저장된 무리가 먼저 돌아온다. 나타날 칸은 OA가 고른다: 원 안의 막히지 않은 바깥 칸을 원 가운데에서 이어 채우기로 훑고(벽·울타리로 막힌 칸은 넘지 않는다), 좀비마다 길찾기는 하지 않는다. 플레이어가 다가올 때 한 번, 게임 1분 이벤트로 거리만 본다 |
| 보급 상자 | 우리 타일(상자 그림 + 용기 속성). 봉인 상태는 오브젝트 modData. 봉인 해제는 시간이 걸리는 행동. 연 상자는 꺼내기만 되고(받는 함수가 아무것도 받지 않음) 비면 부서진다. 들어 옮기지 않는다 |
| 보급 명세서 | 읽을 수 있는 메모 아이템. 내용은 아이템 modData에 넣고 읽기 화면으로 보여 준다 (바닐라 메모·쪽지 아이템으로 가능한지 확인 필요) |
| 아이템 분류 | 아이템 태그와 표시 카테고리 |
| 기계 부품 | 기계 우클릭 → 정비 창에서 부품을 떼고 단다. 달린 부품과 상태는 오브젝트 modData. 부품 아이템은 차 부품처럼 상태 값을 가진다. 모터 소비는 바닐라 발전기의 기기별 소비에 더한다 (`IsoObject.getGeneratorPowerConsumption`과 `couldBePoweredByGenerator` 훅, 확장 API의 기존 power 영역에 함께 넣는다) |
| 주변 감지 | PZ Extension API의 공간 질의. Lua에서 매 프레임 훑지 않는다. |
| 무게 감소 | PZ Extension API로 무게 계산 시점에 보정한다. 아이템 원본의 무게는 바꾸지 않는다. |

### 성능 규칙

매 틱·매 프레임·칸마다 도는 일을 만들지 않는다. 이 장의 각 기능은 아래를 따른다.

| 대상 | 규칙 |
| --- | --- |
| 칸이 불러질 때 할 일 (임무 아이템, 상자 제거·생성, 낙하지 실물, 데드 드롭 용기) | Lua `LoadGridsquare`는 절대 쓰지 않는다. 칸마다 Lua가 불려 차로 달릴 때 초당 수만 번이 된다. 바닐라 Lua 이벤트 `LoadChunk`(청크당 한 번, 8x8칸)를 쓰고, 청크 키로 '대기 표'를 조회한다. 대기 표에 없는 청크는 첫 줄에서 바로 반환한다. 좌표 등록 알림 API는 만들지 않는다. 실측에서 병목으로 보일 때만 다시 올린다 |
| 낙하지 위치 | 세계를 처음 열 때 한 번 정한다. 칸마다 시드를 계산하지 않는다 |
| 무게 보정 (운반 효율, 계열 무게, 옮기는 시간) | API의 Java 쪽에서 아이템 인스턴스의 `displayCategory` 문자열 → 효율 `HashMap`을 둔다. 아이템 종류 → 계열 사전 표는 쓰지 않는다. 정렬 모드가 게임 중에 분류를 바꿔도 따라가기 위해서다. 무게를 셀 때 맵 한 번만 찾는다. 노드를 찍어 효율이 바뀔 때만 맵을 다시 만든다 |
| 육감, 기척 감지 | 불러진 구역의 좀비 목록을 거리로 거른다. 0.5초마다 한 번. 반경이 커져도 비용이 늘지 않는다 (2차 판 무한 반경도 같다). 소리 기척은 바닐라 소리가 날 때 거리만 본다 |
| 시야 보정, 밤눈, 가려진 좀비 수정 | 시야 보정과 밤눈은 바닐라 시야 계산의 각도·어둠 값에 배율이나 가산만 얹는다. 가려진 좀비 수정은 바닐라가 안 그린 좀비 가운데 같은 층이나 바로 위·아래 층, 화면 안, 시야 안인 것만 선 검사한다. 좀비마다 도는 일이라 Lua `OnZombieUpdate`가 아니라 API의 Java 쪽에서 프레임마다 한 번에 처리한다 (Lua판은 초기 시험용). 쿼드트리는 쓰지 않는다: 시야 거리 안의 청크(바닐라가 이미 나눠 둔 격자)에 든 좀비만 보고, 층·거리·원뿔·이미 보임 검사로 거른다. 선 검사 결과는 캐시하지 않는다 (문·물건 변화에 맞춰 지우는 일이 어긋나면 낡은 결과가 남는다). 대신 후보가 된 첫 프레임에 바로 긋고, 그 뒤로는 좀비마다 0.1초 간격으로 다시 긋는다 (시작 프레임을 좀비마다 흩뜨림). 낡은 결과는 길어야 0.1초다. 근거는 아래 측정 |
| 털이 기록, 건물 털이 | 건물에 들어설 때 그 건물 용기 수를 한 번 세어 건물별로 둔다 (API 건물 정보). 용기별 `ItemContainer.isExplored()`로 세고 `BuildingDef.isAllExplored`는 쓰지 않는다(방 단위 플래그). 용기를 열 때·놓고 치울 때만 고친다. 건물 일부가 안 불러져 있으면 '다 뒤짐'을 판정하지 않는다 |
| 아지트 기계 | 틱마다 돌리지 않는다. 시작 시각과 속도를 기록하고 10분마다, 또는 칸이 불러질 때 지난 시간만큼 몰아서 처리한다. 상자째 넣은 큰 묶음도 한 번에 쏟지 않고 몇 개씩 나눠 처리한다 |
| 한꺼번에 담기 | 바닐라 옮기기 행동을 아이템 수만큼 줄 세우지 않는다 (바닐라도 수백 개를 줄 세우면 느려진다). 시간이 걸리는 행동 하나로 한꺼번에 옮긴다 |
| 감정가 표시 | 아이템 종류별 값을 그날 시세로 한 번 계산해 둔다. 툴팁과 견적 창은 표만 읽는다 |
| 설치형 미끼, 기계 소음 | 몇 게임 분마다 소리 하나. 불러지지 않은 곳의 미끼는 아무것도 하지 않는다 |
| 저장 데이터 | 끝없이 자라는 기록에 한도를 둔다. 납품 장부는 마지막 정산 한 줄만 남기고, 시세는 기록하지 않는다. 수신함은 문서 ID만 저장하고 글은 번역 파일에서 읽는다. 끝난 임무는 결과만 남긴다 |
| 헬기 도착, 혈청 기한, 임무 기한 | 10분 이벤트에서 시각만 비교한다. 혈청 기한은 쓸 때만 본다 |
| 감염 지연제의 멈춤, 감염 상태 | 1분 이벤트에서 감염 시작 시각을 고정 나이로 다시 쓴다 (약효 동안만). 몸의 감염을 기록과 맞추는 것도 1분마다 |
| 새 좀비 상처 감지 | 게임에 알리는 이벤트가 없다. `OnPlayerUpdate`에서 `getTimeSinceZombieAttack()` 정수 하나만 읽고(좀비가 공격 상태일 때 갱신마다 0이 된다), 좀비가 공격하고 30갱신 안에서만 부위 열일곱 곳의 상처 플래그를 비교한다 |

| 같은 방식에 좀비별 캐시 (선 83개) | 0.14ms | 0.26ms |
| 쿼드트리를 프레임마다 새로 지음 | 0.98ms | 1.48ms |
| Lua 함수를 좀비마다 호출 (거르기만, 선 검사·Java 객체 접근 없음) | 2.31ms | 4.81ms |

- 시간은 대부분 거르기에 든다. 캐시는 선 수를 1/14로 줄여도 시간은 1할만 줄여서, 낡은 결과의 위험을 질 값이 없다.
- 쿼드트리는 매 프레임 다시 지으면 청크 격자보다 6~8배 느리다. 계속 유지하려면 좀비가 움직일 때마다 고쳐야 하는데, 그건 바닐라
  청크 목록이 이미 하는 일이다.
- Lua 호출만으로도 Java판의 15배다. 실제 `OnZombieUpdate`는 좀비 좌표를 Java 객체에서 읽으므로 더 느리다.
- 모의 시험의 선은 바이트 배열을 걷는다. 게임의 선은 칸 객체를 거쳐서 더 비싸다. 그래서 0.1초 간격 재검사로 선 수에 상한을 둔다
  (60fps에서 프레임당 약 1/6). 실제 비용은 인게임에서 잰다. 시험 코드는 `research/RayBench.java`.

### 에셋

- 그림은 바닐라 타일을 빌리지 않고 직접 만든다. 모양과 상태를 우리가 정하고, 다른 모드가 같은 바닐라 타일을 건드려도 겹치지
  않는다. Building Utilities의 `tools/tile_art.py`(입체를 게임의 2:1 시점으로 그려 128×256 타일, `.tiles`, `.pack`, 아이템
  아이콘을 만든다)를 가져와 쓴다. 타일셋 이름과 tiledef 번호는 이 모드 것을 새로 정한다 (BU와 설치된 모드들이 쓰지 않는 수).
- 타일 (돌릴 수 있는 것은 네 방향):
  - 통신 단말과 정식 단말 (꺼짐 / 켜짐)
  - 납품 상자 (열림 / 밀봉), 보급 상자 (봉인 / 열림), 낙하산 달린 상자 (투하 연출)
  - 대량 분해기, 재단기, 프로판 정제기, 오일 정제기, 목재 절단기 (멈춤 / 도는 중)
  - 연구팀 보관함, 대형 빗물 저장소, 설치형 미끼 (켜짐 / 꺼짐)
  - 크기 (2026-10-09): 큰 시설은 여러 칸이다. 2×1은 분해대, 대량 분해기, 재단기, 목재 절단기, 연구팀 보관함. 2×2는 프로판
    정제기, 오일 정제기, 대형 빗물 저장소. 나머지(통신 단말, 상자들, 설치형 미끼)는 한 칸. 칸마다 오브젝트 하나를 두고 상태와
    용기는 기준 칸(가장 작은 x, y)에만 둔다. 설치·회수·회전은 덩어리째 한다.
- 아이템 아이콘: 위 설치물, 강화 혈청(트리 셋 + 공용), 치료 혈청, 감염 역전제, 지연제 둘, 검사 키트, 정식 단말, 시료 묶음, 운석 파편, 조립법 책자, 보급 명세서,
  임무 아이템, 개조 키트 넷, 기계 부품(등급은 색으로 구분), 연구팀 배낭, 채취용 메스, 정밀 핀셋, 좀비 시료 넷(등급은
  색으로 구분), 임무 시료.
- 연구팀 배낭의 3D 모델도 직접 만든다. 움직임 없는 낮은 폴리곤 배낭이라 스크립트로 만들 수 있다.
  - 바닐라 메는 배낭은 뼈대에 붙은 메시다 (`Bag_ALICEpack.xml`: `m_Static` false, `skinned/backpacks/m_alice_pack`, 남녀 따로).
    모델 파일 `.x`는 글자로 된 형식(`xof 0303txt`)이라 직접 써낼 수 있다.
  - 몸통에 정적 모델을 붙이는 바닐라 예가 없다 (`m_AttachBone`은 머리·팔다리·골반뿐). 그래서 바닐라 배낭과 같은 길로 가되, 모든
    꼭짓점을 배낭 전용 뼈 `Bip01_BackPack` 하나에 100% 묶는다. 뼈 이름은 바닐라 배낭 `.x`에서 읽는다.
  - 우리 메시를 직접 만드는 것이 목표다. 메시 제작이 실패하면 대안으로 바닐라 ALICE `.x`를 복사해 새 텍스처만 입힌다.
  - 필요한 것: 멘 모습(남·녀), 손에 든 모습(왼손·오른손, 바닐라 `ALICE_Pack_LHand/RHand.x`처럼), 바닥에 놓인 모습(`.fbx`),
    텍스처. 수통 걸이 위치도 모델에 맞춘다.
  - 몸과 옷에 파묻히는지는 인게임 스크린샷으로 확인하며 맞춘다.
- 트리 화면의 노드 아이콘(트리 33개 + 2차 판 22개)은 단순한 평면 그림으로 일관되게 그린다.
- 소리는 바닐라 헬기 소리를 쓴다.

## 13. 구현 범위와 순서

- 목표는 처음부터 이 문서 전체(3차 연구판 제외)다. 작은 첫 버전을 따로 떼어 내지 않는다. 스펙을 다 잠근 뒤 서로 기대지 않는
  시스템(거래·헬기, 트리 셋과 2차 판, 상점과 신뢰도 보상, 임무, 아지트 기계, 개조 키트, 에셋)을 나눠 함께 만든다.
- 만드는 순서는 핵심 순환부터: 도감 → 첫 보급과 통신 단말 → 납품·헬기·정산 → 상점과 강화 혈청 → 트리. 그 위에 나머지를 얹는다.
- 확장 API에 기대는 노드(무게, 용량 상한, 주변 감지, 시야)는 API 작업과 맞물린다. 스펙을 잠그면 이 모드가 API에 요구하는 기능
  목록을 먼저 뽑아 API 작업에 넘긴다.

### 이 모드에 넣지 않는 것

- 건물 배관·전력 (LG 모드 대체). 별도의 전기/배수 모드로 만든다. 두 모드 모두 PZ Extension API(구역·전력·급수
  등)를 쓴다.

## 14. 정하지 않은 것

설계는 잠겼다 (2026-10-09). 남은 것은 구현하며 확인할 것뿐이다.

- 수치: [수치표](NUMBERS.md)의 기본값으로 시작하고 실제 플레이에서 맞춘다. 정적 검토로는 더 맞추지 않는다.
- 게임 안에서 확인할 것: 설정집 8장(월드 연출 부품, 성씨 대조), [가능성 조사](FEASIBILITY.md)의 인게임 점검표.
- 루트 리스폰: 막지 않는다 (REWARDS '정할 것').
- 멀티플레이: 막지 않지만 검증하지 않는다. 납품 상자의 발신기는 플레이어별로 둔다.
