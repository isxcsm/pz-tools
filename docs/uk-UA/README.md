# PZ Tools

PZ Tools — неофіційна програма для Windows, що створює резервні копії та відновлює збереження Project Zomboid. Для підтримуваного формату також доступне відновлення персонажа. Це не продукт The Indie Stone.

<a id="features"></a>
## Можливості

Ручні й заплановані копії, історія зі змінними назвами, мініатюрами й даними персонажа, імпорт/експорт ZIP, лікування та воскресіння поза активною грою. Інтерфейс, типові назви нових копій і повідомлення про збереження підтримують 18 мов. Є теми, необов'язковий режим системного трея, індикатори перебігу та фільтри журналу.

<a id="getting-started"></a>
## Встановлення й запуск

Потрібні **Windows x64** і **[середовище виконання .NET 10](https://dotnet.microsoft.com/en-us/download/dotnet/10.0)** для Windows x64. Наразі програма запитує права адміністратора для відстеження змін файлів через USN. Опублікований пакет містить компоненти WinUI та невелике середовище Java для з'єднання з грою, але не її JAR-файли.

Готові пакети шукайте в [Releases](https://github.com/isxcsm/pz-tools/releases). Якщо пакета ще немає, скористайтеся інструкцією зі збирання нижче. **Source code ZIP із GitHub — не готова до запуску програма**.

1. Розпакуйте **весь** пакет в одну теку та запустіть `PzTools.App.exe`. Не переносіть лише EXE й не змішуйте файли різних збірок.
2. У налаштуваннях перевірте теку збережень і виберіть окрему теку копій. Не використовуйте теку збережень гри як місце для резервних копій.
3. Виберіть збереження, створіть ручну копію та перевірте повідомлення про завершення. Задайте інтервал і кількість автоматичних копій.
4. Перед оновленням закрийте PZ Tools і розпакуйте весь новий пакет в іншу теку. Збереження та копії тримайте окремо від файлів програми.

Налаштування й службові дані містяться в `%LOCALAPPDATA%\PzTools`, копії — у вибраній теці. Див. [розміщення файлів (корейською)](../deployment-layout.md).

<a id="backups-and-retention"></a>
## Зберігання та видалення копій

Початкові значення — **5 хвилин** і **20 автоматичних копій**. Вмикайте й вимикайте автоматичні копії окремим перемикачем. Інтервал від 1 до 60 хвилин зберігається після вимкнення. Воно працює з активним збереженням; перезапуск програми починає новий інтервал. Наявні налаштування залишаються.

Ручні копії можна перейменовувати; ліміт автоматичних копій їх не враховує. **Це не безстрокове зберігання:** явне видалення або очищення після зникнення початкового збереження може видалити й їх. Перед видаленням чи переміщенням оригіналу експортуйте важливі копії в ZIP на інший накопичувач.

Видалення лише копії не змінює поточне збереження, але цю копію вже не можна відновити чи експортувати. Видалення збереження через програму прибирає і його копії. Місце може звільнитися пізніше; файли не завжди зменшуються одразу. Див. [налаштування (корейською)](../configuration.md) і [правила очищення (англійською)](../repository-housekeeping.md).

<a id="game-saving"></a>
## Збереження гри перед копіюванням

Необов'язкове з'єднання просить активну гру зберегтися перед копіюванням файлів. Воно завантажує JVM-агент і викликає `GameWindow.save(true)` в ігровому потоці, без мода Workshop чи зміни встановлених файлів гри. Функція експериментальна для перевіреної структури **Build 42 / Java 25 в одиночній грі**; багатокористувацька гра не підтримується.

Збереження й п'ятисекундний відлік мають окремі перемикачі. **«Гру збережено» не означає «Резервна копія готова»:** далі відбуваються збирання та стиснення файлів. Без з'єднання або для неактивного збереження копіюються лише дані, вже записані на диск. Невдалий чи невизначений запит не позначається успішним. Див. [інтеграцію з грою (англійською)](../save-bridge.md).

<a id="restore-and-archives"></a>
## Відновлення й архіви ZIP

Перед відновленням вийдіть із вибраного збереження. Виберіть копію та перевірте підтвердження: **поточні файли буде замінено, а прогрес після створення цієї копії — втрачено**. Якщо відновлення перервано, відкрийте PZ Tools знову й перевірте стан до завантаження гри. Не вважайте автоматичне повернення до попереднього стану гарантованим.

Поточне збереження чи копію можна експортувати в ZIP, а ZIP перевірити перед імпортом. Довгострокові архіви тримайте поза текою копій програми. Копія на тому самому накопичувачі не захищає від його поломки. Відповідні операції описані в [командах CLI (корейською)](../cli.md).

<a id="character-recovery"></a>
## Відновлення персонажа

Спершу створіть ручну копію або ZIP: **відновлення персонажа не робить додаткової копії початкових файлів**. Воно змінює лише поточне неактивне збереження, а не давні копії. Підтримуються **Build 42.20.4, формат світу 249, один локальний гравець (ID 1)**.

Лікування чи воскресіння відновлює здоров'я та усуває підтримувані травми й тимчасові стани. Позитивні й негативні риси, досвід, навички, рецепти та наявний інвентар зберігаються. Це не постійний імунітет; не всі ефекти модів усуваються.

Якщо смерть спорожнила інвентар, речі повертаються із зомбі або тіла персонажа, а джерело видаляється. Посвідчення особи не потрібне. Стан речей, вміст сумок, одяг і дані кріплень зберігаються. Збережені ID відновлюють предмети в руках, якщо доступні; інакше їх треба спорядити знову. Втрачені речі не створюються. За непевної ідентифікації змін не буде. [відновлення та обмеження (англійською)](../character-recovery.md)

<a id="backup-engine"></a>
<a id="compatibility-and-limits"></a>
## Зберігання й сумісність

Рушій зберігає змінені дані, а не дублює все збереження щоразу. За наявності використовує NTFS USN, інакше — повне сканування з порівнянням вмісту. Перевірка копій і стиснення Brotli типово ввімкнені; дедуплікація необов'язкова. Відповідь гри та перевірки окремих файлів **не гарантують, що всі файли відображають той самий момент**.

Проєкт перебуває в розробці до випуску. Несумісне сховище відхиляється з `repository-reset-required`, без автоматичного перетворення чи видалення. Виберіть **нову порожню теку копій**, зберігши стару за потреби. **Не видаляйте `Zomboid/Saves` або окремо `repository.db`, щоб обійти помилку.** Див. [формат сховища (корейською)](../repository-format.md) і [розширені налаштування (англійською)](../runtime-configuration.md).

<a id="troubleshooting"></a>
## Пошук проблем і звіти

Якщо програма не запускається, перевірте середовище виконання й повноту пакета. Якщо файл зайнятий чи постійно змінюється, дочекайтеся завершення збереження гри перед повторною копією. Якщо автоматичні копії не створюються, перевірте інтервал, активне збереження й чи працює PZ Tools; закриття в трей не завершує програму.

Після помилки чи часткового виконання прочитайте журнал до повторення операції. Перерване відновлення або редагування персонажа потрібно перевірити до завантаження гри. У [повідомленні про проблему](https://github.com/isxcsm/pz-tools/issues) вкажіть версію чи коміт програми, версію гри, кроки та потрібні записи журналу. Приберіть особисті шляхи й приватні дані; не додавайте все збереження без потреби.

<a id="building"></a>
## Збирання з джерельного коду

Потрібні Windows, .NET SDK із `global.json`, PowerShell 7, Windows x64 Java 25 JDK і засоби C++/WinUI Visual Studio. Виконайте команди з кореня репозиторію, замінивши приклад шляху до JDK:

```powershell
$jdk = 'C:\path\to\jdk-25'
dotnet build PzTools.sln -c Release -p:Platform=x64 -p:JdkPath="$jdk"
dotnet test tests/PzTools.Backup.Tests -c Release -p:JdkPath="$jdk"
pwsh scripts/publish-app.ps1 -JdkPath $jdk -Output artifacts/app-local
```

Скрипт публікації готує програму й робочі процеси разом у **новій або порожній теці**. Для повторної публікації використовуйте інший шлях. [Розробка й перевірки (англійською)](../development.md) описує залежності, тести пакета, CLI та перевірки з явним увімкненням.
