# PZ Tools

**Ви дбаєте про виживання. PZ Tools зберігає точку повернення.** Автоматичні копії, історія збережень і відновлення персонажа в Project Zomboid.

## Можливості

- Визначає активне збереження; типово створює копію кожні **5 хвилин** і залишає **20 автоматичних копій**.
- Ручні копії можна перейменовувати; ліміт автоматичних копій їх не видаляє.
- Необов'язковий виклик `save(true)` через JVM-агент перед копіюванням і відлік 5 секунд у грі, без мода Workshop.
- Мініатюри, ім'я персонажа, час виживання й позначка смерті.
- Інкрементальне відстеження USN, стиснення й необов'язкова дедуплікація; без USN — повне сканування з типовим порівнянням хешів.
- Перевірка, імпорт та експорт ZIP, індикатори перебігу й журнали.
- Лікування та воскресіння поза грою зі збереженням позитивних і негативних рис, навичок та досвіду.

## Початок роботи

Потрібні **Windows x64 і середовище виконання .NET 10**. Запустіть `PzTools.App.exe` і перевірте теки збережень та копій. Створіть ручну копію або грайте з автоматичними. Інтервал `0` вимикає їх. Перед відновленням копії чи персонажа вийдіть із відповідного збереження.

## Обмеження

Відновлення персонажа змінює лише поточне збереження, не попередні копії. Підтримуються **Build 42.20.4, формат світу 249 та один локальний гравець (ID 1)**. Речі можна повернути з єдиного відповідного запису власного зомбі за збереженою позицією та ім'ям у посвідченні. Зомбі, що перемістилися, цілі без посвідчення й тіла в чанках мапи не підтримуються. Негативні риси залишаються; ефекти модів можуть зберегтися.

Міст збереження — експериментальна функція для одного гравця Build 42 / Java 25, яку можна вимкнути. Повідомлення про завершення збереження у грі не означає готовність резервної копії та не гарантує атомарного знімка світу.

Ручні копії можна видалити явно; вони також підлягають очищенню осиротілих копій, якщо початкове збереження зникне. Важливі копії експортуйте на інший носій.
