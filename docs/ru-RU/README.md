# PZ Tools

PZ Tools — неофициальное приложение Windows для резервного копирования и восстановления сохранений Project Zomboid. Для поддерживаемого формата доступно восстановление персонажа. Это не продукт The Indie Stone.

<a id="features"></a>
## Возможности

Ручные копии и копии по расписанию, переименовываемая история с миниатюрами и данными персонажа, импорт/экспорт ZIP, лечение и воскрешение вне активной игры. Интерфейс, стандартные имена новых копий и уведомления о сохранении поддерживают 18 языков. Есть темы, необязательный режим системного трея, индикаторы выполнения и фильтры журнала.

<a id="getting-started"></a>
## Установка и запуск

Требуются **Windows x64** и **[среда выполнения .NET 10](https://dotnet.microsoft.com/en-us/download/dotnet/10.0)** для Windows x64. Сейчас приложение запрашивает права администратора для отслеживания изменений через USN. Пакет приложения содержит компоненты WinUI и небольшую среду Java для подключения к игре, но не игровые JAR-файлы.

Готовые пакеты проверяйте в [Releases](https://github.com/isxcsm/pz-tools/releases). Если пакет ещё не опубликован, воспользуйтесь сборкой из исходников ниже. **Source code ZIP на GitHub — не готовое к запуску приложение**.

1. Распакуйте пакет **целиком** в одну папку и запустите `PzTools.App.exe`. Не переносите только EXE и не смешивайте файлы разных сборок.
2. В настройках проверьте папку сохранений и выберите отдельную папку резервных копий. Не используйте папку игровых сохранений как место для копий.
3. Выберите сохранение, создайте ручную копию и проверьте сообщение о завершении. Настройте интервал и количество автоматических копий.
4. Для обновления закройте PZ Tools и распакуйте весь новый пакет в другую папку. Сохранения и копии храните отдельно от файлов приложения.

Настройки и служебные данные находятся в `%LOCALAPPDATA%\PzTools`, копии — в выбранной папке. См. [размещение файлов (корейский)](../deployment-layout.md).

<a id="backups-and-retention"></a>
## Хранение и удаление копий

Начальные значения — **5 минут** и **20 автоматических копий**. Интервал `0` отключает автоматическое копирование. Оно работает с активным сохранением; перезапуск приложения начинает новый интервал. Имеющиеся настройки сохраняются.

Ручные копии можно переименовывать; они не учитываются в лимите автоматических копий. **Это не бессрочное хранение:** явное удаление или очистка после исчезновения исходного сохранения может удалить и их. Перед удалением или перемещением оригинала экспортируйте важные копии в ZIP на другой накопитель.

Удаление только копии оставляет текущее сохранение, но эту копию уже нельзя восстановить или экспортировать. Удаление сохранения через приложение удаляет и его копии. Освобождение места может произойти позже; размер файлов не всегда уменьшается сразу. См. [настройки (корейский)](../configuration.md) и [правила очистки (английский)](../repository-housekeeping.md).

<a id="game-saving"></a>
## Сохранение игры перед копированием

Необязательное подключение просит активную игру сохраниться до копирования файлов. Оно загружает JVM-агент и вызывает `GameWindow.save(true)` в игровом потоке, без мода Workshop и изменения установки игры. Это экспериментальная функция для исследованной структуры **Build 42 / Java 25 в одиночной игре**; многопользовательская игра не поддерживается.

Сохранение и пятисекундный отсчёт включаются отдельно. **«Игра сохранена» не означает «Резервная копия готова»:** затем выполняются сбор файлов и сжатие. Без подключения или для неактивного сохранения копируются только данные, уже записанные на диск. Неудачный или неопределённый ответ не считается успехом. См. [подключение к игре (английский)](../save-bridge.md).

<a id="restore-and-archives"></a>
## Восстановление и архивы ZIP

Выйдите из выбранного сохранения перед восстановлением. Выберите копию и проверьте подтверждение: **текущие файлы будут заменены, а прогресс после создания этой копии потерян**. При прерывании снова откройте PZ Tools и проверьте состояние до загрузки сохранения в игре. Не считайте автоматический возврат к прежнему состоянию гарантированным.

Текущее сохранение или копию можно экспортировать в ZIP, а ZIP — проверить перед импортом. Долгосрочные архивы храните вне папки копий приложения. Копия на том же накопителе не защищает от его поломки. Эквивалентные операции перечислены в [командах CLI (корейский)](../cli.md).

<a id="character-recovery"></a>
## Восстановление персонажа

Сначала создайте ручную копию или ZIP: **восстановление персонажа не делает дополнительную копию исходных файлов**. Оно меняет только текущее неактивное сохранение, а не прошлые копии. Поддерживаются **Build 42.20.4, формат мира 249, один локальный игрок (ID 1)**.

Лечение или воскрешение восстанавливает здоровье и снимает поддерживаемые травмы и временные состояния. Положительные и отрицательные черты, опыт, навыки, рецепты и существующий инвентарь остаются. Постоянный иммунитет не предоставляется; не все эффекты модов удаляются.

Если инвентарь погибшего пуст, вещи возвращаются только из единственной подходящей записи его зомби по сохранённой позиции и имени в удостоверении личности. Переместившиеся зомби, цели без удостоверения и тела в чанках карты не поддерживаются. Предметы в руках может потребоваться назначить заново. См. [восстановление и ограничения (английский)](../character-recovery.md).

<a id="backup-engine"></a>
<a id="compatibility-and-limits"></a>
## Хранение и совместимость

Движок сохраняет изменения, а не полную копию всей игры каждый раз. Используется NTFS USN, если доступен; иначе — полное сканирование с сопоставлением содержимого. Проверка копий и сжатие Brotli включены по умолчанию, дедупликация — дополнительно. Ответ игры и проверки отдельных файлов **не гарантируют, что все файлы отражают один и тот же момент**.

Проект находится на стадии разработки до выпуска. Несовместимое хранилище отклоняется с `repository-reset-required`, без автоматического преобразования или удаления. Выберите **новую пустую папку резервных копий**, сохранив прежнюю, если данные нужны. **Не удаляйте `Zomboid/Saves` или отдельно `repository.db` ради обхода ошибки.** См. [формат хранилища (корейский)](../repository-format.md) и [расширенные настройки (английский)](../runtime-configuration.md).

<a id="troubleshooting"></a>
## Поиск проблем и сообщения об ошибках

Если приложение не запускается, проверьте среду выполнения и полноту пакета. Если файл занят или постоянно меняется, дождитесь сохранения игры перед повторной попыткой копирования. Если автоматических копий нет, проверьте интервал, активное сохранение и работу PZ Tools: закрытие в трей не завершает приложение.

После ошибки или частичного завершения прочитайте журнал перед повторением операции. Прерванное восстановление или редактирование персонажа требует проверки до загрузки игры. В [сообщении об ошибке](https://github.com/isxcsm/pz-tools/issues) укажите версию или коммит приложения, версию игры, шаги и нужные записи журнала. Удалите личные пути и конфиденциальные данные; не прикладывайте всё сохранение без необходимости.

<a id="building"></a>
## Сборка из исходников

Нужны Windows, .NET SDK из `global.json`, PowerShell 7, Windows x64 Java 25 JDK и средства C++/WinUI Visual Studio. Выполните команды из корня репозитория, заменив пример пути к JDK:

```powershell
$jdk = 'C:\path\to\jdk-25'
dotnet build PzTools.sln -c Release -p:Platform=x64 -p:JdkPath="$jdk"
dotnet test tests/PzTools.Backup.Tests -c Release -p:JdkPath="$jdk"
pwsh scripts/publish-app.ps1 -JdkPath $jdk -Output artifacts/app-local
```

Скрипт публикации готовит приложение и рабочие процессы вместе в **новой или пустой папке**. Для повторной публикации используйте другой путь. [Разработка и проверки (английский)](../development.md) описывает зависимости, тесты пакета, CLI и проверки с явным включением.
