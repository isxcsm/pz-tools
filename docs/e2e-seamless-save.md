# 끊김 없는 저장 0.9.1 — E2E 후보 확인

이 문서는 실제 게임에서 아직 검증하지 않은 결과를 확인하는 절차입니다.
합성 JVM 테스트 통과가 드래그·프레임 시간·차량 복원 검증을 대신하지는 않습니다.
이 후보는 저중단 저장이며 모든 직렬화가 논블로킹이거나 월드 전체가 원자적 스냅샷이라는 보장은 없습니다.

## 실행 준비

- 기존 앱과 게임을 완전히 종료한 뒤 후보 폴더의 `PzTools.App.exe`를 실행합니다.
  앱·작업 프로그램·JAR을 일부만 교체하지 않습니다. Bootstrap API 8 / 모듈 0.9.1입니다.
- Windows x64와 .NET 10 x64 런타임이 필요합니다. 서명되지 않은 테스트용 빌드입니다.
- 반드시 버려도 되는 새 테스트 월드를 사용합니다. 중요한 원본 월드로 실패·강제 종료 검사를 하지 않습니다.
- 백업 위치는 **새 테스트 전용 폴더**로 설정합니다. 기존 백업 위치를 유지한 채 세이브 루트만
  축소하면 기존 고아 백업 정리 정책에 영향을 줄 수 있으므로 그렇게 설정하지 않습니다.
- 첫 비교는 자동 백업을 끄고 수동 백업으로 수행합니다. 기존 설정은 이 빌드에서도 유지되므로
  확장 토글과 백업 위치를 직접 확인합니다. `백업 전 게임 저장`은 켜둡니다.

## 기본 저장과 비교

같은 월드·장소·모드 조합에서 확장을 끈 저장과 켠 저장을 각각 반복합니다.
첫 연결/클래스 준비 시간을 일상적인 저장 시간과 혼동하지 않습니다.
확장을 켠 경우 카드가 실제로 확장 저장 완료를 보고했는지 확인합니다.
`기본 저장 사용`과 사유 코드가 표시되었다면 확장 성능을 검사한 것이 아닙니다.

| 확인 | 기대 동작 |
| --- | --- |
| 아이템을 계속 끌고 있는 중 저장 요청 | 드래그 종료를 기다리지 않고 저장이 실행되어야 합니다. 저장 때문에 드래그·아이템·포커스가 바뀌면 실패입니다. |
| 버튼 해제 직후, UI의 드롭 처리 전 저장 | 저장이 별도 UI 갱신을 끼워 넣지 않아야 합니다. 이후 정상 입력 처리에서 드롭이 한 번만 완료되어야 합니다. |
| 텍스트 선택·모달 조작·일반 버튼 유지 | 특정 UI 상태 때문에 저장을 보류하지 않습니다. 정상 조작·취소를 되돌리거나 끝난 드래그를 복구하면 안 됩니다. |
| 일반 게임 저장·다른 모드의 저장 | 원래 진입점과 미리보기 동작을 유지합니다. 동일 데이터의 의존 잠금 대기는 가능하며 무간섭을 보장하지 않습니다. |

드래그 검사는 게임 포커스를 유지한 상태에서 정기 백업이 실행되도록 합니다. 앱으로 전환해
수동 백업을 누르면 포커스 변경 자체가 조작에 영향을 줄 수 있습니다. 저장 완료 전에 드래그를
풀지 않아도 요청이 진행되는지 확인합니다. 일시정지·저장 작업 준비 조건은 별개로 유지됩니다.

## 보존·취소·복귀 확인

발견만 하고 타지 않은 차량, 컨테이너에서 옮긴 아이템, 모드의 저장 데이터를 기록한 뒤
초기 백업과 다음 증분 백업을 각각 **별도 복원 위치**에 복원하여 게임에서 확인합니다.
세이브 폴더에 파일이 생겼다는 사실만으로 데이터 보존을 판정하지 않습니다.

정기 백업은 일시정지 중 대기하고, 사망 백업은 같은 캐릭터의 실제 JVM 사망 사건을 사용해야 합니다.
저장 시작 전 취소는 쓰기를 시작하지 않아야 하며, 시작 후 취소는 완료 불명일 수 있습니다.
이때 진행 중인 쓰기를 버리거나 기본 저장을 중복 실행하면 안 됩니다.
확장을 끄면 다음 요청은 기본 저장을 사용합니다. 버전 미지원으로 복귀한 경우도 구분합니다.
네이티브 쓰기·일반 저장·종료 경합은 테스트 월드에서만 확인합니다.

## 결과를 남길 항목

문제가 생긴 시각, 확장 켜짐 여부, 실제 제공자/복귀 코드, 드래그/아이템 이동 상황,
카드의 게임 스레드 준비 시간과 전체 완료 시간을 남깁니다.
상세 저장 결과에는 다음 마이크로초 단위 진단값도 포함됩니다.

| 필드 | 의미 |
| --- | --- |
| `chunkCount` | 측정된 전용 청크 저장 호출 수 |
| `chunkBodyUs` | 청크 본문 점유 시간. 직렬화·원래 잠금 등을 포함하고 별도 측정한 쓰기 전달 시간은 제외 |
| `chunkHandoffUs` | 쓰기 전달·잠금 확보·동기 대체 쓰기에 사용한 게임 스레드 시간 |
| `animalSaveUs`, `collisionSaveUs` | 해당 저장 **호출**의 게임 스레드 점유 시간. 비동기 완료 전체 시간이 아님 |
| `otherCaptureUs` | 위 구간 외의 준비 시간 |

이 값들은 프레임 시간 통계나 FPS가 아닙니다. 새 게임 프로세스나 상시 로그 수집기를 만들지 않으며
현재 요청의 합계만 기록합니다. 큰 청크 직렬화·동물 저장·잠금·새 파일 생성 등으로 지연이 남을 수 있습니다.
실게임 인수 결과가 확인되기 전에는 `dev`/`main` 병합이나 일반 배포용 완성본으로 취급하지 않습니다.
