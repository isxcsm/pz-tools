# PZ Tools

PZ Tools は Project Zomboid のセーブをバックアップ・復元する Windows アプリです。対応するセーブ形式ではキャラクターの回復も行えます。The Indie Stone の公式製品ではありません。

<a id="features"></a>
## 主な機能

手動・自動バックアップ、名前を付けられるバックアップ履歴、サムネイルとキャラクター情報、ZIP のインポート・エクスポート、プレイ終了後の治療・蘇生に対応します。画面、新しいバックアップの既定名、ゲーム保存通知は18言語に対応しています。テーマ、システムトレイ、進捗表示、ログの絞り込みも利用できます。

<a id="getting-started"></a>
## インストールと起動

**Windows x64** と Windows x64 用の **[.NET 10 ランタイム](https://dotnet.microsoft.com/en-us/download/dotnet/10.0)** が必要です。現在のアプリは USN によるファイル変更追跡のため管理者権限を要求します。配布パッケージには WinUI とゲーム接続用の小型 Java ランタイムが含まれます。ゲームの JAR は含まれません。

実行用パッケージは [Releases](https://github.com/isxcsm/pz-tools/releases) で確認してください。未公開の場合は下記のソースビルド手順を使用します。GitHub の **Source code ZIP は実行用アプリではありません**。

1. パッケージを**すべて**同じフォルダーに展開して `PzTools.App.exe` を起動します。EXE だけを移したり、異なるビルドのファイルを混ぜたりしないでください。
2. 設定でセーブフォルダーを確認し、別のバックアップフォルダーを指定します。ゲームのセーブフォルダーをバックアップ先にしないでください。
3. セーブを選んで手動バックアップを作成し、アプリで完了を確認します。自動バックアップの間隔と保持数も設定します。
4. 更新時は PZ Tools を終了し、新しいパッケージ一式を別のフォルダーに用意します。セーブとバックアップはアプリのファイルとは分けて保管します。

設定・管理データは `%LOCALAPPDATA%\PzTools`、バックアップは指定したフォルダーに保存されます。[配布・データ配置（韓国語）](../deployment-layout.md)も参照してください。

<a id="backups-and-retention"></a>
## バックアップの保持と削除

初期設定は**5分間隔、自動バックアップ20件保持**です。 自動バックアップのスイッチでオン・オフを切り替えます。間隔は1～60分で設定し、オフにしても保持されます。自動バックアップはプレイ中のセーブを対象とし、アプリを再起動すると新しい間隔を開始します。既存の設定は維持します。

手動バックアップは名前を変更でき、自動バックアップの件数制限から除外されます。ただし**永久保存ではありません**。明示的な削除や、元のセーブがなくなった後の整理では手動バックアップも削除されます。元のセーブを削除・移動する前に、重要なバックアップを ZIP にエクスポートして別のドライブに保管してください。

バックアップだけを削除した場合、現在のセーブは残りますが、そのバックアップは復元・エクスポートできなくなります。アプリからセーブを削除すると対応するバックアップも削除します。空き領域の回収は後から行われることがあり、直ちにファイルサイズが縮むとは限りません。[設定（韓国語）](../configuration.md)・[整理方針（英語）](../repository-housekeeping.md)に詳細があります。

<a id="game-saving"></a>
## バックアップ前のゲーム保存

任意の接続機能は、ファイルのコピー前にプレイ中のゲームへ保存を要求します。JVM エージェントを読み込み、ゲームスレッドで `GameWindow.save(true)` を呼び出します。Workshop MOD やゲームインストールファイルの変更は不要です。確認済みの **Build 42 / Java 25 シングルプレイ**構造を対象とする実験的機能で、マルチプレイには対応していません。

ゲーム保存と5秒カウントダウンは個別に切り替えられます。**「ゲーム保存完了」は「バックアップ完了」ではありません。** その後にファイル収集・圧縮が続きます。接続を無効にした場合や非プレイ中のセーブでは、ディスクに書かれた内容だけをバックアップします。保存要求が失敗した場合や応答が不明な場合は成功と表示しません。[ゲーム保存連携（英語）](../save-bridge.md)を参照してください。

<a id="restore-and-archives"></a>
## 復元と ZIP の入出力

復元対象のセーブのプレイを終了してください。バックアップを選び、確認画面の対象を確認します。**復元は現在のファイルを置き換えるため、そのバックアップ以降の進行状況は失われます。** 中断した場合はゲームでセーブを開く前に PZ Tools を再起動し、状態を確認してください。自動的に元に戻ったと決めつけないでください。

現在のセーブやバックアップを ZIP に書き出し、ZIP の内容を確認してからインポートできます。長期保存用 ZIP はアプリのバックアップフォルダー外に保管してください。同じドライブ上のバックアップではドライブ故障に対応できません。[CLI 操作（韓国語）](../cli.md)にも対応するコマンドがあります。

<a id="character-recovery"></a>
## キャラクター回復

先に手動バックアップか ZIP エクスポートを行ってください。**キャラクター回復は元のファイルの追加バックアップを作りません。** 非プレイ中の現在のセーブだけを変更し、過去のバックアップは編集しません。対応範囲は **Build 42.20.4、ワールド形式249、ローカルプレイヤー1人（ID 1）**です。

治療・蘇生は体力と対応する負傷・一時的状態を回復します。有利・不利な特性、経験値、スキル、レシピ、既存の所持品は維持します。永続的な耐性は付与せず、MOD 固有の効果をすべて解除するわけではありません。

死亡したキャラクターの所持品が空の場合、保存位置と身分証の名前が一意に一致する本人のゾンビ記録からのみ回収できます。移動済みのゾンビ、身分証のない対象、マップチャンク内の死体は対象外です。手に持つ装備は再設定が必要な場合があります。[回復機能の制限（英語）](../character-recovery.md)を確認してください。

<a id="backup-engine"></a>
<a id="compatibility-and-limits"></a>
## 保存方式と互換性

毎回セーブ全体を複製せず、変更されたデータを保存します。利用できる場合は NTFS USN を使い、使えない場合は全体走査と内容比較へ切り替えます。コピー検証と Brotli 圧縮は標準で有効、重複排除は任意です。ゲーム保存の応答とファイル単位の検証は、**すべてのファイルが厳密に同じ瞬間の状態であることを保証しません**。

正式配布前の開発段階のため、互換性のないバックアップ保存先は `repository-reset-required` で拒否します。自動変換・自動削除はありません。**新しい空のバックアップフォルダー**を選び、必要な旧バックアップはフォルダーごと残してください。**このエラーの対処として `Zomboid/Saves` や `repository.db` だけを削除しないでください。** 現行形式は[保存形式（韓国語）](../repository-format.md)、詳細設定は[実行設定（英語）](../runtime-configuration.md)に記載しています。

<a id="troubleshooting"></a>
## 問題の確認と報告

起動できない場合はランタイムと配布ファイル一式を確認してください。使用中・変更中のファイルによるエラーは、ゲームの保存が終わってからバックアップを再試行します。自動バックアップが動かない場合は間隔、プレイ中のセーブ、PZ Tools が起動中かを確認します。トレイへ閉じる操作はアプリの終了ではありません。

失敗・一部完了の操作は繰り返す前にログを確認してください。復元やキャラクター編集が中断した場合、ゲームを再開する前の確認が必要です。[Issue](https://github.com/isxcsm/pz-tools/issues) にはアプリのバージョン・コミット、ゲームのバージョン、再現手順、関連ログを記載してください。個人情報を含むパスなどを除き、不要なセーブ一式は添付しないでください。

<a id="building"></a>
## ソースからのビルド

Windows、`global.json` 指定の .NET SDK、PowerShell 7、Windows x64 Java 25 JDK、Visual Studio の C++・WinUI ビルドツールが必要です。リポジトリのルートで、例の JDK パスを置き換えて実行します。

```powershell
$jdk = 'C:\path\to\jdk-25'
dotnet build PzTools.sln -c Release -p:Platform=x64 -p:JdkPath="$jdk"
dotnet test tests/PzTools.Backup.Tests -c Release -p:JdkPath="$jdk"
pwsh scripts/publish-app.ps1 -JdkPath $jdk -Output artifacts/app-local
```

発行先は**新しいフォルダーまたは空のフォルダー**にします。アプリとワーカーが一緒に用意されるので、再発行時は別の出力先を選んでください。[開発・検証手順（英語）](../development.md)に依存関係、配布テスト、CLI、明示的な有効化が必要なテストをまとめています。
